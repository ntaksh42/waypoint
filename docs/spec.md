# waypoint 仕様書

| | |
|---|---|
| 版 | `Cargo.toml` の `version` を正とする |
| 対象 | Windows 10 22H2 以降 |

Windows 向けの常駐型ランチャー。Quick Launch で登録した場所やアプリを検索して一手で移動・起動する。Quick Access Popup の中核機能をベースに、フォルダ移動を主軸としつつアプリ起動・ブックマーク検索まで扱う汎用ランチャーとして再構成したもの。

Azure DevOps 検索 (`az `、FR-9.18 系) は分量が多いため [spec-azure.md](spec-azure.md) に分けた。

---

## 01. 概要

### 目的

日常的に使う場所・ウィンドウ・アプリ・情報への到達コストをゼロに近づける。デスクトップのショートカット、エクスプローラーのクイックアクセス、タスクバーのピン留め、ブラウザのブックマーク、Alt+Tab、スタートメニュー検索に分散している導線を、Quick Launch に集約する。Windows 向け汎用ランチャーとして、検索できる対象の広さと動作の速さの両方で他のランチャー（Flow Launcher、PowerToys Run 等）に劣らないことを目指す。

### 想定ユーザー

作成者本人のみ。複数プロジェクトのソースツリー、ビルド出力、ログ、ドキュメントの各フォルダを一日に何十回も行き来する開発者。設定ファイルを直接編集することに抵抗がなく、GUI とテキストの両方から設定を触りたい。

### 成功の判定

本人が 2 週間連続で毎日使い、既存のショートカット群を消しても不便を感じないこと。それ以外の指標（ユーザー数、配布、ストア公開）は追わない。

### 非目標

- テキスト展開・ホットストリングは対象外。キーストローク送出のミニ言語は実装しない
- 自前のファイルインデックスは作らない。ファイルシステムの全件走査は行わない（アプリ起動はスタートメニュー / インストール済みショートカットの列挙に限る）。PC 全体のファイル名検索は Everything（別プロセス）へ問い合わせるだけで、waypoint 自身は何も索引化しない
- 第三者への配布を前提としない。自動更新、多言語化は作らない
- ただし**インストーラ (MSI) は作る**。自分の複数マシンへ同じ構成で入れ直すため（02 章参照）
- ファイラー固有の操作 API には対応しない。新規表示は Windows の既定フォルダーハンドラーに従う

## 02. スコープ

機能ごとに扱いを決める。**採用** は作る。**保留** は着手の条件を詰めてから再検討する。**除外** は作らないと決めたもので、再検討もしない。何をするかは各 FR に書き、ここには判定の理由だけを置く。

### 採用

| 機能 | 理由・前提 | FR |
|---|---|---|
| Quick Launch | 本体。キーボードだけで目的の場所・アプリへ移る | 9 |
| フォルダ・ファイル項目 | 本体 | 3, 4 |
| 特殊フォルダ / My Special Folders | KNOWNFOLDERID の対応表を持つだけで済む | 3 |
| サブメニュー・区切り・アイコン | 登録数が 20 を超えると階層化が必須になる | 3 |
| 変数展開 | ネットワークパスとプロファイル配下のパスが長い | 5 |
| 管理 GUI | 本人の希望 | 6 |
| フォルダ構造の一括取り込み | 登録作業を短縮する | 6.9 |
| Recent / Frequent Folders | 作業中の場所へ素早く戻る | 9.2 |
| Current Windows (`w `) | 開いている Explorer とアプリのウィンドウへ切り替える | 9.15 |

| Claude Code / Codex の起動・再開 (`cc ` `cx ` `cs `) | フォルダへ移動して起動・`--resume` する手間を省く | 9.15.4〜9.15.6 |
| Git ブランチ名の表示 | 同じリポジトリの複数ワークツリーを見分ける | 9.6 |
| 設定のマシン間持ち出し (`shared.json`) | 複数マシンへ同じ構成で入れ直す。主体が 1 人なので「設定同期」(除外) とは別 | 7.7 |
| Web 検索 (`??`) | 主要ランチャーの多くが持つ。URL を組み立てるだけで済む | 9.21 |
| Help | プレフィックスとキーが増え、覚えきれない | 9.22 |
| パス直接入力・Tab 補完・配下へ潜る | 未登録のパスへも同じ窓から移る。「ライブフォルダ」(保留) と違い、`Tab` を押したときだけ 1 階層を列挙する | 9.24〜9.26 |
| プロセス Kill (`k `) | 「選んだら即実行」に揃え、確認ダイアログを設けない | 9.15.2 |
| インストーラ (MSI) | 自分の複数マシンへ同じ構成で入れ直す | — |

### 保留

| 機能 | 着手の前に決めること |
|---|---|
| ライブフォルダ | フィルタ仕様の範囲 (10 章) |
| ファイルダイアログ内のフォルダ切替 | ダイアログの判定方法 (10 章) |
| 電卓 | 式パーサの精度 (浮動小数点・単位換算) |
| システムコマンド (シャットダウン・スリープ・ロック) | 誤実行を防ぐ確認の要否 |
| クリップボード履歴 | 常時監視の常駐コストをトリガー経路から外す設計 |

### 除外

| 機能 | 理由 |
|---|---|
| ポップアップメニュー | Quick Launch へ一本化した |
| Reopen a Folder | Current Windows と重複する |
| スニペット / ホットストリング | キーストローク送出のミニ言語が要る |
| PowerShell PROFILE の関数実行 | 常駐コストが `pwsh` に依存する。Windows Terminal から直接呼べる |
| プレースホルダ | 実質的に式評価エンジン。変数展開で足りる |
| グループ一括起動 | 起動遅延とエラー時の中断制御が要る |
| 共有メニュー / 複数ユーザーの設定同期 | 単一ユーザー |
| FTP サイト | 用途なし |
| 電源操作・ウィンドウ管理 | ランチャーの責務ではない |
| 他ファイラー固有連携 (DOpus / TC) | OS の既定フォルダーハンドラーで足りる |
| 自動更新・多言語 | 配布しない |

> **スコープを守るための約束**
>
> 「除外」に入れた項目は、実装中に思いついても着手しない。追加したくなった場合は本表を書き換えてから着手する。**仕様書を更新せずに機能を足すことを禁止する。** 追加する機能は Quick Launch の表示遅延 50ms (06 章) を損なわないことを確かめる。

## 03. 用語

| 用語 | 定義 |
|---|---|
| 項目 | Quick Launch の候補元となる設定項目。フォルダ・特殊フォルダ・サブメニュー・区切りのいずれかの型を持つ |
| メニュー | 設定項目を分類する入れ子のリスト。Quick Launch では候補のパンくずとして使う |
| トリガー | Quick Launch を表示させる入力操作。グローバルホットキー、トレイアイコンの左クリック、または二重起動 |
| 元ウィンドウ | Quick Launch を開いた時点で最前面だったウィンドウ。`reuse` の対象を決めるために保持する |
| 設定ファイル | 項目定義とアプリ設定を保持する JSON ファイル。単一ファイルとする |
| 常駐部 | トレイに常駐しトリガーを待ち受けるプロセス |
| 管理画面 | 項目を編集するウィンドウ。必要時のみ生成する |

## 04. 機能要件

FR-1 (トリガー) と FR-2 (ポップアップメニュー表示) は欠番。ポップアップメニューを除外したため (02 章)。Quick Launch のトリガーは FR-9.1 にある。

### FR-3 項目の型

| 型 | 保持する情報 | 選択時の動作 |
|---|---|---|
| `folder` | 表示名、パス、開き方、ブランチ表示の可否 | 指定パスを既定のフォルダーハンドラーで開く |
| `file` | 表示名、パス | 指定ファイルを既定の関連付けアプリで開く（`newWindow`/`reuse` の概念を持たない） |
| `specialFolder` | 表示名、既知フォルダ ID | 解決したパスを既定のフォルダーハンドラーで開く |
| `submenu` | 表示名、子項目の配列 | Quick Launch の候補にパンくずを付ける |
| `separator` | 表示名（省略可） | Quick Launch の候補にはしない |

### FR-4 フォルダを開く動作

- **FR-4.1** 開き方は `newWindow`（既定のフォルダーハンドラーで開く）と `reuse`（元ウィンドウのフォルダを変更）の 2 種。既定は `newWindow`
- **FR-4.2** `reuse` は元ウィンドウがエクスプローラーである場合のみ有効。それ以外は `newWindow` にフォールバックする
- **FR-4.3** `Shift` を押しながら選択した場合、項目の設定に関わらず `newWindow` で開く
- **FR-4.4** 開いたウィンドウは、トリガーが発生したモニタ上に配置する

### FR-5 変数展開

- **FR-5.1** パス中の `%NAME%` を Windows 環境変数として展開する
- **FR-5.2** パス中の `{NAME}` を設定ファイル内のユーザー変数として展開する
- **FR-5.3** 展開は項目の選択時ではなく設定の読み込み時に一度だけ行い、結果をメモリに保持する
- **FR-5.4** 解決できない変数を含む項目は起動時のログに記録し、Quick Launch の候補には含めない。アプリは停止しない

### FR-6 管理画面

- **FR-6.1** エクスプローラー型のレイアウトで、左に候補グループのツリー、右に選択中グループの項目一覧を表示する。上部のツールバーに作成・編集・整理の操作を機能グループ別（Add / Edit・Remove・Duplicate / Copy・Paste・Move...）に並べ、変数と Quick Launch の設定を別タブにまとめる
- **FR-6.2** 項目の追加・編集・削除・複製ができる
- **FR-6.3** 一覧内で項目の順序を上下ボタンで変更できる。加えて、行をドラッグして任意の位置へ落とすことでも並べ替えられる。ドラッグ中は挿入位置を線で示す
- **FR-6.4** フォルダ選択ダイアログ（`folder`）またはファイル選択ダイアログ（`file`）からパスを指定できる
- **FR-6.5** エクスプローラーからのドラッグ＆ドロップで項目を追加できる。フォルダは `folder`、ファイルは `file` として追加する
- **FR-6.6** 保存ボタンで設定ファイルへ書き出し、常駐部へ再読み込みを通知して Quick Launch のインデックスを再構築する。保存前に閉じようとした場合は確認する
- **FR-6.7** ユーザー変数を編集する画面を持つ
- **FR-6.8** Quick Launch のホットキーを編集する設定画面を持つ。保存は設定ファイルへの保存と常駐部への再読み込みまで完了させる
- **FR-6.8.1** ホットキーは文字列の直接入力に加え、実際のキー入力から設定できる。記録中は打鍵を OS へ渡さず、`Win+W` のようにシステムが予約している組み合わせもそのまま記録できる。`Esc` で取り消す
- **FR-6.9** 起点フォルダと探索深度（0〜10）を指定し、サブフォルダ構造を候補グループとして一括取り込みできる。取り込み前に名称変更と除外ができ、確定後は通常の項目編集・並べ替えを利用できる
- **FR-6.10** 取り込みは確定時の一度だけ行い、元フォルダとの自動同期は行わない
- **FR-6.11** 一覧の行は Ctrl+クリック（トグル）・Shift+クリックまたは Shift+矢印（範囲選択）・Ctrl+A（全選択）で複数選択できる。削除・上下移動・複製・コピー＆ペーストは選択中の全項目へまとめて適用される。バラバラな選択で上下移動する場合、端に達する項目が一つでもあれば全体を動かさない
- **FR-6.12** 複数選択時、Edit は共有プロパティ一括編集ダイアログを開く。Open mode（New window / Reuse / 変更しない）と Show Git branch name（On / Off / 変更しない）の 3 状態を選択項目全体へ適用する
- **FR-6.13** 選択中の項目（単一・複数とも）は「Move...」で別の候補グループ（サブメニュー）の末尾へまとめて移動できる。移動先が選択項目自身の配下を指す場合は何もしない
- **FR-6.14** 右ペインに全グループ横断の検索ボックスを持つ（`Ctrl+F` でフォーカス、`Esc` でクリア）。名前またはパス/ターゲットへの部分一致（大小文字を区別しない）で全グループを再帰的に検索し、ヒットした項目の種別・所属グループ・詳細を一覧表示する。行を選ぶと該当グループへ切り替えて選択状態にし、検索を閉じて通常表示に戻る。検索中は一覧の編集操作（追加・編集・削除・並べ替え等）を無効化する
- **FR-6.15** 左の候補グループツリーと「Move...」の移動先選択には、それぞれ名前の部分一致で絞り込むフィルター欄を持つ。一致したグループだけでなく、そこへ至る祖先グループも表示に残す

> 管理画面は .NET 8 + WPF の別プロセスとして実装する。必要時だけ起動し、常駐部と Quick Launch の起動時間・メモリ・メッセージループへ影響させない。

### FR-7 設定の永続化

- **FR-7.1** 設定は `%APPDATA%\waypoint\config.json` に保存する
- **FR-7.2** 起動時に設定ファイルが無い場合、既定の設定を生成する
- **FR-7.3** 保存時、既存ファイルを退避してから書き込む（temp に書いて置換する原子的更新）
- **FR-7.4** JSON の解析に失敗した場合、空の Quick Launch 候補で起動し、トレイ通知でエラーを知らせる。設定ファイルは上書きしない
- **FR-7.5** 手編集を想定し、インデント 2 桁・日本語は非エスケープ・**項目順を保存で入れ替えない**（`serde_json` の `preserve_order`）
- **FR-7.6** Recent Items の利用回数は `%APPDATA%\waypoint\history.json` にローカル保存する。外部へ送信しない
- **FR-7.7** 設定保存時、環境非依存な `settings`（Quick Launch・Azure DevOps プロジェクト一覧）を `%APPDATA%\waypoint\shared.json` へも複製書き出しする。起動時、`shared.json` が存在すれば `config.json` 読み込み後にその `settings` で上書きする（`shared.json` が同期の正とする）。`items`・`variables` は環境依存のため対象外。ユーザーが `shared.json` を Git やクラウド同期フォルダへ置くことで複数マシン間の設定持ち出しに使う。waypoint 自身は同期処理（Git 操作・アップロード等）を行わない
- **FR-7.8** 登録済みの `folder` / `file` 項目（メニュー階層全体）のうち、パスが存在しなくなったものを config から削除し、Quick Launch の候補からも外す。起動時と以後 10 分おきにバックグラウンドスレッドで存在確認し、UI スレッドでは結果の反映と保存だけを行う（トリガー経路には入れない）。ドライブ未接続・VPN 切断などの一時的な不在で消さないよう、**パスのルート（`C:\` や `\\server\share\`）が存在するのに対象だけが無い場合に限り**削除する。ルートが見えない項目・変数を解決できない項目・相対パスは判定せず残す。削除した項目はログへ残す

### FR-8 常駐とライフサイクル

- **FR-8.1** 起動時にタスクトレイへ常駐する。ウィンドウは表示しない
- **FR-8.2** トレイアイコンの右クリックメニューに「設定を開く」「設定を再読み込み」「終了」を持つ
- **FR-8.3** 二重起動を抑止する。二つ目のプロセスは既存プロセスにメニュー表示を要求して終了する
- **FR-8.4** Windows 起動時の自動実行を設定で切り替えられる

### FR-9 Quick Launch

FR-9 は次の節に分けている。FR 番号はコードやコミットから参照されているため、並べ替えても番号は変えていない。

| 節 | FR |
|---|---|
| 表示とトリガー | 9.1, 9.10, 9.11, 9.12, 9.12.1 |
| 検索と順位 | 9.2〜9.6, 9.9, 9.27 |
| キー操作 | 9.7, 9.8 系 |
| プレフィックス一覧 | 各プレフィックスの横断表 |
| ブラウザ (`b ` `h ` `t `) | 9.13, 9.17, 9.17.1, URL の重複判定 |
| アプリ・ウィンドウ・プロセス (`a ` `w ` `k `) | 9.14, 9.15, 9.15.2 |
| フォルダを別のアプリで開く (`ps ` `ed ` `cc ` `cx ` `cs ` `vs `) | 9.15.1, 9.15.3〜9.15.6, 9.23 |

| 内部コマンド | 9.20, 9.22 |

#### 表示とトリガー

- **FR-9.1** 設定可能なグローバルホットキー（既定 `Alt+Space`）で検索画面を開く。`RegisterHotKey` が失敗した場合は低レベルキーボードフックで同じキーを横取りする
- **FR-9.10** 検索画面は常駐プロセス内の標準 Win32 コントロールで実装し、管理画面プロセスを起動しない
- **FR-9.11** 検索画面は黒を基調とし、`Segoe UI Variable Text`、Windows 11 の角丸・ダークタイトルバー、青系の選択色を使う。選択行は行全体を青で塗り、検索語に一致した箇所は青の下線付き太字で示す。未対応環境では通常の Win32 表示へフォールバックする
- **FR-9.12** 候補行と画面の描き方
  - 候補はフォルダーアイコン、名前、パンくずとパスの 2 段を高密度に描画し、長いパスは中央を省略して末尾のフォルダ名・ファイル名を残す
  - パンくずがパスの先頭部分と同じ場合（`E:\` と `E:\waypoint` 等）はパスだけを、開いているウィンドウはプロセス名だけを出し、同じ情報を 2 度並べない
  - 行の右端には種別タグ（Folder / Window / App 等）を、選択行では代わりに Enter で行う操作（Open / Switch 等）を表示する。区分見出し付きの絞り込みなし一覧では、種別は見出しが示すので非選択行の種別タグを省く。区分見出しには件数を添える
  - ウィンドウ下端には選択中の候補で実際に使えるキー操作（例: フォルダなら `Enter` / `Shift+Enter` / `Ctrl+E` / `Ctrl+C` / `Ctrl+Shift+Enter`、ウィンドウなら `Enter` / `Ctrl+W`）のヒントと、選択位置（`3 / 24`）を表示し、空の検索欄には検索対象の案内文を出す
  - DPI に応じてフォント・余白・行高を拡縮する。表示件数は 12〜24 件、既定は 12 件とする
- **FR-9.12.1** 検索画面を表示するモニターを設定で選べる。`primary`（プライマリモニター、既定）と `cursor`（マウスカーソルのあるモニター）の 2 択で、いずれもそのモニターの作業領域の中央に表示する。モニター内の位置指定や絶対座標は持たない（DPI・解像度・モニター構成の変更で画面外へ出る可能性を排除するため）。DPI はモニターごとに異なるため、選んだモニターの実効 DPI で寸法を決める

#### 検索と順位

- **FR-9.2** 登録済みの `folder` / `file` / `specialFolder`、設定で有効にした Recent / Frequent Folders、Current Windows、ブックマーク、アプリを、プレフィックスなしの通常入力でも横断して検索対象にする。ブラウザ履歴（FR-9.17）は件数が多くキー入力ごとの全件走査が体感の重さに直結するため対象外とし、`h ` のプレフィックスモード限定のままとする。Everything（FR-9.16）と Azure DevOps（FR-9.18）は外部 IPC / API / DB を伴うため対象外とし、`f ` / `az ` のプレフィックスモード限定のままとする
- **FR-9.3** 項目名と所属サブメニューのパンくずを、大文字小文字を区別しない部分一致で検索する。空白区切りの語は AND 条件とする
- **FR-9.4** パス検索は設定で有効化できる。検索中にパスの存在確認やネットワークアクセスを行わない
- **FR-9.5** 名前の完全一致、先頭一致、単語境界一致、部分一致、パンくず一致、パス一致の順に候補を並べる。直接一致しない場合は、文字順・連続性・単語境界を考慮した Fuzzy 検索で名前、パンくず、パス（FR-9.4 が有効な場合）を照合する。同点ではメニュー順を保つ
- **FR-9.6** 候補には名前、パンくず、解決済みパスを表示し、同名項目を判別できるようにする。`folder` 候補は `showBranch` 継承規則で Git ブランチ名を行の右端にタグとして表示する。取得はインデックス構築時にまとめて行い、検索・描画の経路では `.git` を読まない
- **FR-9.9** 検索インデックスは起動時、設定再読み込み時、動的メニュー更新後に構築する。キー入力時はメモリ上の検索だけを行う
- **FR-9.27** かな/カナのみで構成される項目名は、ローマ字・ひらがな・カタカナの混在入力でも音で一致する（例: `でぃすこ-do` / `ディスコード` / `disuko-do` / `でぃすこーど`）。入力のローマ字部分だけをひらがなへ変換し、カタカナはひらがなへ正規化して、項目名の読みの部分一致で判定する。長音は `-` と `ー` を同一視する。ローマ字の変換規則は IME に従う（`di` は「ぢ」、「でぃ」は `dhi`）。未確定の子音（`k` など）はローマ字のまま扱う。数字・記号を含む入力は対象外。対象は項目名がかな/カナのみの候補で、漢字を含む名前は対象外（読みを持たない）。他の一致段階（FR-9.5）より下位で、新たな IPC・I/O は伴わない

#### キー操作

- **FR-9.7** `Up` / `Down` / `Home` / `End` / `PageUp` / `PageDown` で候補を移動し、`Enter` で実行、`Esc` またはフォーカス喪失で閉じる
- **FR-9.8** `Shift+Enter` は常に `newWindow`、`Ctrl+Enter` は常に `reuse` として開く。開き方を持たない候補（Current Windows・ブックマーク・アプリ）はこの修飾を無視する。ただし `az ` モードの入力中は FR-9.18 の Live 検索を優先する
- **FR-9.8.1** `Ctrl+Shift+Enter` で選択中の候補を設定のルートメニュー末尾へ追加登録する（お気に入り昇格）。対象はフォルダ・ファイル・Everything の検索結果・アプリのみで、永続化できないウィンドウ（Current Windows）と URL（ブックマーク。`b ` で既に検索できるため）は無音で無視する。同じパスを持つ項目がメニュー階層のどこかに既にあれば（大文字小文字を区別せず）追加しない。ウィンドウは閉じず、続けて他の候補も登録できる
- **FR-9.8.2** `Ctrl+C` は選択中候補のパスをクリップボードへコピーする。通常は検索窓 (Edit) にフォーカスを置いたまま上下キーで候補を選ぶため、リストにフォーカスがある場合だけでなく検索窓にある場合も対象とする。ただし検索窓で文字列が選択されているときは Edit 本来のテキストコピーを優先し、この動作を割り込ませない。コピーする値は候補が持つパス文字列そのもので、URL を持つ候補（ブックマーク・ブラウザ履歴・タブ・Azure DevOps）では URL になる
- **FR-9.8.3** `Ctrl+E` は選択中候補をエクスプローラーで開き、対象自体を選択状態にする（`explorer.exe /select,`）。ウィンドウは閉じる
- **FR-9.8.4** `Ctrl+Alt+Enter` は選択中候補を管理者として実行する（`ShellExecuteW` の verb を `runas` にする）。対象はアプリ（`LaunchApp`）と既定ハンドラーで開く候補（`OpenWithDefaultHandler`、Everything の検索結果）のみ。フォルダは `Shift`/`Ctrl` を newWindow/reuse に使っており（FR-9.8）修飾が衝突するため対象外とし、昇格の概念を持たない候補（Current Windows・ブックマーク・ブラウザ履歴・タブ・Web 検索・内部コマンド）は無音で無視して通常の Enter と同じ扱いにする。UAC の同意ダイアログは Windows が出すため waypoint 自身は確認を挟まない。ユーザーが同意を拒否した場合（`ERROR_CANCELLED`）はエラー表示をしない
- **FR-9.8.5** `Ctrl+W` は選択中の Current Windows 候補の実ウィンドウへ `WM_CLOSE` を送って閉じる（`w ` モードに限らず通常入力でも有効）。対象はウィンドウ候補（`FocusWindow`）のみで、他の候補は無音で無視する。強制終了ではなく通常の閉じる操作と同じなので、未保存の確認ダイアログ等はアプリ側が出す。閉じた候補は索引と一覧から即座に外し、検索画面は閉じず選択位置を保ったまま続けて他のウィンドウも閉じられる

#### ブラウザ (`b ` `h ` `t `)

- **FR-9.13** ブックマークは FR-9.2 により通常入力でも検索対象になる。入力が `b ` (半角スペース込み) で始まる間はブックマークだけに絞り込み、残りの文字列で検索する。選択すると既定ブラウザで URL を開く。外部から届く URL（ブックマーク・タブ・Azure DevOps）は `http` / `https` のみ開き、`file:` や `ms-msdt:` など他の scheme は開かない。ブックマーク取り込みは設定で無効化できる。重複 URL は「URL の重複判定」のとおり畳む。ブックマークは Chrome と Edge をまたいで畳み、代表は名前が空でないもの（同条件なら先に読んだもの）
- **FR-9.17** 入力が `h ` (半角スペース込み) で始まる間は通常の検索対象を隠し、Chrome / Edge の既定プロファイルの閲覧履歴だけを残りの文字列で検索する。選択すると既定ブラウザで URL を開く。履歴取り込みは設定で無効化でき、URL も検索対象にする。履歴 DB の読取は FR-9.9 のインデックス更新時に限定し、キー入力・表示の経路では行わない。重複 URL は「URL の重複判定」のとおり畳む。履歴は Chrome と Edge をまたいで畳み、代表は最新訪問のもの
- **FR-9.17.1** 入力が `t ` (半角スペース込み) で始まる間は通常の検索対象を隠し、Chrome / Edge の現在開いているタブだけをタイトルと URL で検索する
  - 選択すると、拡張経由で対象ブラウザのウィンドウとタブを前面化する。Edge のスリーピングタブなどで Native Messaging host が接続されていない場合は、保持済み URL を既定ブラウザで開く
  - タブのタイトル・URL・ID はメモリだけに置き、設定・履歴・ログへ保存しない
  - Native Messaging host の manifest と Chrome / Edge のユーザー登録は waypoint 起動時に更新する。初回の対話的 MSI インストール完了後は、拡張を読み込むローカル案内ページを自動で開く
  - 拡張またはブラウザが未起動でタブを 1 件も受け取っていない間は、タブの代わりに導入案内ページ (`browser-tabs\setup.html`) を開く候補 1 件だけを返す (入力した検索語に関係なく出す。使用履歴・お気に入りには載せない)
  - タブ変更時のスナップショット更新だけを受け、Quick Launch の表示・キー入力時にブラウザへ同期問い合わせを行わない
  - 拡張はタブ変更時しか一覧を送らないため、Native Messaging host は最後に受けた一覧を控え、waypoint の起動時（再起動・MSI 更新後を含む）と、ウィンドウを開いてから初めて `t ` が 0 件だったときに、常駐部からの `PostMessage` で再送を求められたらそれを送り直す（控えが無ければ拡張へ再送を頼む）。この要求は待たない非同期通知で、表示・キー入力の経路をブロックしない

##### URL の重複判定

ブックマーク (FR-9.13) と履歴 (FR-9.17) の重複 URL は、`src/url_key.rs` の正規化キーで 1 件に畳む。

- http / https の差・ホストの大小文字・パス末尾の `/`・フラグメントを無視し、SPA のルート (`#/` `#!`) と実クエリは保持する
- `utm_*` / `fbclid` / `gclid` などのトラッキングクエリは除去し、Learn の `tabs` も無視する
- パス・クエリの大小文字は区別する
- キーは判定専用で、開く URL は代表のものをそのまま使う
- ブックマークと履歴は別モードなので相互には畳まない

#### アプリ・ウィンドウ・プロセス (`a ` `w ` `k `)

- **FR-9.14** アプリは FR-9.2 により通常入力でも検索対象になる。入力が `a ` (半角スペース込み) で始まる間はスタートメニューのショートカット (`.lnk`) だけに絞り込み、残りの文字列で検索する。選択すると対象アプリを起動する。アプリ検索は設定で無効化できる
- **FR-9.15** Current Windows は FR-9.2 により通常入力でも検索対象になる。入力が `w ` (半角スペース込み) で始まる間は Current Windows だけに絞り込み、残りの文字列で検索する。選択すると対象ウィンドウへ切り替える。Current Windows の取り込みは設定で無効化できる。検索はウィンドウタイトルに加え所有プロセスの実行ファイル名にもマッチする（`w chrome` のようにタイトルへアプリ名が出ないウィンドウも見つけられる）
- **FR-9.15.2** 入力が `k ` (半角スペース込み) で始まる間は通常の検索対象を隠し、実行中プロセスをスナップショット (`CreateToolhelp32Snapshot`) から実行ファイル名で検索する。同名プロセスが複数あればプロセスごとに 1 件として列挙し（PID を候補の区別表示に使う）、`waypoint.exe` / `waypoint-settings.exe` 自身は自己終了事故を防ぐため候補から常に除外する。Enter で選択したプロセスへ確認なしで即座に `TerminateProcess` する（他の候補と同じ「選んだら即実行」の操作感に揃え、破壊操作専用の確認ダイアログは設けない）。管理者権限プロセス等 UIPI で終了に失敗する場合は例外化せず黙って無視する（FR-9.4 のネットワークパス確認と同じ扱い）。開き方（newWindow/reuse）・お気に入り昇格・使用頻度履歴の概念は持たない

#### フォルダを別のアプリで開く (`ps ` `ed ` `cc ` `cx ` `cs ` `vs `)

- **FR-9.15.1** 入力が `ps ` (半角スペース込み) で始まる間は、フォルダを指すパスを持つ既存候補（config 登録の folder/specialFolder、Recent/Frequent Folders）だけに絞り込み、残りの文字列で検索する。Everything 結果は対象外（別インデックス系統で、混ぜると実装が複雑になるため）。新規のデータソースは持たず、通常検索と同じインデックスへの絞り込みフィルタとして実装する。選択すると `wt.exe -d <path> pwsh` で Windows Terminal 上に PowerShell 7 を明示的に指定して起動する（Windows Terminal の既定プロファイル設定には依存しない）。`wt.exe` または `pwsh` が見つからない場合は `powershell.exe -NoExit -WorkingDirectory <path>`（Windows 標準の PowerShell 5.1）にフォールバックする。開き方（newWindow/reuse）の概念は持たない
- **FR-9.15.3** 入力が `ed ` (半角スペース込み) で始まる間は、`ps ` と同じフォルダ候補だけに絞り込み、選択すると `settings.quickLaunch.editorCommand` を実行してフォルダパスを 1 引数として渡す。既定値は VS Code の `code`。設定画面では実行ファイル名または絶対パスだけを設定し、追加引数のパースは持たない。新規データソースを持たず、キー入力時はメモリ上の索引だけを検索する。開き方（newWindow/reuse）・お気に入り昇格の概念は持たない
- **FR-9.15.4** 入力が `cc ` (半角スペース込み) で始まり、まだ確定フォルダ + 半角スペースが先頭に来ていない間は、`ps `/`ed ` と同じフォルダ候補だけに絞り込み、残りの文字列で検索する。フォルダ候補を選択すると即実行はせず、検索欄を `cc <folder> ` に補完してカーソルを末尾へ置く。続けて `cc <folder> [sessionname]` の形式で確定候補を 1 件だけ組み立てる。`folder` はフォルダ候補の選択で確定済みの 1 トークンなので空白を含められるが、そのぶん `sessionname` に空白は含められない（末尾の最後の半角スペースが区切り）。`sessionname` は省略可能で、省略した場合は表示名を付けずに起動する。選択すると `wt.exe -d <folder> <pwsh.exe> -NoExit -Command claude` （`sessionname` があれば `--name <sessionname>` を付ける）で PowerShell 7 上の Claude Code を起動し、Windows Terminal または PowerShell 7 が見つからなければ Windows PowerShell を同じ作業ディレクトリで開いて同じコマンドを実行する。フォルダ存在確認とプロセス起動は最後の確定候補を選択したときだけに行い、開き方（newWindow/reuse）・お気に入り昇格・使用頻度履歴の対象外とする
- **FR-9.15.5** 入力が `cx ` (半角スペース込み) で始まる間は、`ps `/`ed ` と同じフォルダ候補だけに絞り込み、残りの文字列で検索する。Codex CLI には表示名を指定する起動オプションが無いため、`cc ` と違って検索欄の補完は挟まず、フォルダ候補の選択で即起動する。選択すると `wt.exe -d <folder> codex` で Codex CLI を起動し、Windows Terminal が起動できなければ Windows PowerShell を同じ作業ディレクトリで開いて `codex` を実行する。フォルダ存在確認とプロセス起動は選択時だけに行い、開き方（newWindow/reuse）・お気に入り昇格・使用頻度履歴の対象外とする
- **FR-9.15.6** 入力が `cs ` (半角スペース込み) で始まる間は通常の検索対象を隠し、Claude Code と Codex CLI の過去のセッションを、最終更新の新しい順に残りの文字列で検索する。候補名はセッションのタイトル、パンくずは種別・作業フォルダ・最終更新からの経過時間とし、フォルダ名でも絞り込める。
  - Claude Code は `~/.claude/projects/*/*.jsonl` を対象とし、タイトルは `custom-title`（`/rename` 等で付けた名前）を `ai-title`（自動生成）より優先する。記録は数十 MB に達するため全体は読まず、先頭と末尾の各 64KB だけを読む。タイトルの無いセッション（`/clear` だけで終わったもの等）は候補に出さない。選択すると作業フォルダで `claude --resume <id>` を起動する
  - Codex は `~/.codex/session_index.jsonl` の `thread_name` をタイトルとし、作業フォルダは `~/.codex/sessions/**/rollout-*-<id>.jsonl` 先頭行の `session_meta.cwd` から得る。選択すると作業フォルダで `codex resume <id>` を起動する
  - 起動は `cc ` / `cx ` と同じく Windows Terminal + PowerShell 7（見つからなければ Windows PowerShell）で行う
  - 読み取りは Quick Launch の表示のたびに専用スレッドで行い、更新日時が変わっていないファイルは読み直さない。`cs ` の入力経路では直近の読み取り結果を引くだけで、ファイル I/O を行わない。そのため起動後に初めて表示してすぐ `cs ` を打った場合、初回の読み取りが終わるまで一覧は空になる
  - 開き方（newWindow/reuse）・お気に入り昇格・使用頻度履歴の対象外とする
- **FR-9.23** `vs ` は通常候補を隠し、VS Code / Cursor の最近のワークスペースを検索する。バッジは `WORKSPACES`。名前とフルパス・エディター名を表示し、リモートは `Remote` タグで区別する。Enter で該当エディターの `--folder-uri` / `--file-uri` に渡す。Ctrl+C はローカルパスまたはリモート URI をコピーし、Ctrl+E はローカルだけ選択表示する。お気に入り昇格・使用頻度履歴の対象外。
  - `%APPDATA%/Code` / `Cursor` の `User/globalStorage/state.vscdb` の `history.recentlyOpenedPathsList` を読む。Code は新形式の `%USERPROFILE%/.vscode-shared/sharedStorage/state.vscdb` も先に探す。履歴の配列順を最近順として使い、履歴が読めない場合は `User/workspaceStorage/*/workspace.json` の `folder` / `workspace` をディレクトリ更新日時の新しい順に読む。通常ファイルの履歴は対象外。Insiders・VSCodium・Windsurf は対象外。
  - 列挙・JSON/SQLite 読み取り・存在確認は専用背景スレッドで行う。読み取り完了から 5 秒は再走査しない。ローカルの削除済み対象は除外し、UNC は存在確認を省いてネットワーク待ちを避ける。リモートの存在確認は行わない。表示・打鍵では直近のメモリ上の結果だけを使い、背景読み取り完了時に一覧を更新する。
  - `settings.quickLaunch.includeEditorWorkspaces` は既定 true。無効時は読み取りも検索もしない。未導入・欠落・破損したストアは空として扱い、エディターのデータは変更しない。

#### 外部への検索 (`f ` `??` `az `)

- **FR-9.16** 入力が `f ` (半角スペース込み) で始まる間は通常の検索対象を隠し、常駐中の Everything へ IPC (`WM_COPYDATA`) で問い合わせて結果をそのまま並べる。Enter でエクスプローラーの既定ハンドラーで開く。Everything が見つからない・応答しない場合は 0 件を返し、エラー表示はしない。Everything 連携は設定で無効化できる（既定オン。設定項目を省略した場合も有効）
- **FR-9.16.1** `f ` モード中、`Alt+C` (Match Case) / `Alt+W` (Match Whole Word) / `Alt+R` (Regex) で Everything IPC の検索フラグをトグルできる。トグルすると同じクエリを新しいフラグで即座に再送する。アクティブなフラグは検索窓の `FILES` バッジの左に短いピルで表示する。フラグの状態は `f ` モードを抜けても保持し、次に `f ` へ入ったときも引き継ぐ（プロセス内メモリのみ、設定ファイルへは保存しない）
- **FR-9.21** 入力が `??` で始まる間は通常の検索対象を隠し、Web 検索の確定候補を 1 件だけ表示する。`??` の後ろの文字列（前後の空白を除く）をそのまま検索語とし、`??` 直後の半角スペースは任意とする（`?? rust` と `??rust` を同じに扱う）。選択すると既定ブラウザで検索 URL を開く。検索エンジンは設定で 1 つだけ選び（既定 Google、他に Bing / DuckDuckGo / Brave)、テンプレートの `{query}` を URL エンコードした検索語で置換する。検索語が空（`??` のみ）のときはエンジンのトップページを開く候補を出す。サジェスト（入力補完）は取得しない — 打鍵ごとのネットワーク呼び出しは FR-9.9 の「キー入力時はメモリ上の検索だけを行う」と表示レイテンシの優先度に反するため。新規のデータソース・インデックスを持たず、候補は入力から組み立てる静的な 1 件なので、インデックス構築時の I/O も伴わない。検索語は毎回異なりうるため Recent/Frequent の使用履歴には記録せず、お気に入り昇格（FR-9.8.1）の対象にもしない。Web 検索は設定で無効化できる（既定オン）
- **FR-9.18** Azure DevOps 検索 (`az `)。FR-9.18〜FR-9.18.10 は [spec-azure.md](spec-azure.md) にある

#### パス入力

- **FR-9.24** 入力（前後の空白と二重引用符を除去）が `X:\` / `X:/` で始まる、または `\` で始まる（UNC）とき、通常の検索結果の先頭に「そのパスを開く」候補を 1 件出す。`/` は `\` に正規化する。候補は name = 末尾のセグメント（ルートは入力そのまま）、breadcrumb = `Path`、`OpenFolder`（`Shift+Enter` / `Ctrl+Enter` で newWindow / reuse、FR-9.8）。相対パス・`C:` のみ・URL は候補にしない。FR-9.4 の制約どおり**入力中に存在確認やネットワークアクセスは行わない**（存在しないパスは Enter 時に開けず無反応）。履歴への記録はしない。お気に入り昇格（FR-9.8.1）の対象にはなる
- **FR-9.25** パス入力中（FR-9.24 の候補が出ている間）の `Tab` は、最後のセグメントを前方一致（大文字小文字無視）するディレクトリを補完する。1 件なら `名前\` まで確定し、複数なら共通接頭辞まで補完して該当ディレクトリを候補に並べる。以後の `Tab` / `Shift+Tab` で候補を順 / 逆順に巡る。末尾が `\` のときの `Tab` は直下のディレクトリを一覧表示する。巡回中でない `Shift+Tab` は 1 階層上へ戻る（ドライブルート・UNC の共有ルートより上へは上がらない）。列挙は `Tab` の明示操作のときだけ別スレッドで行い（UI スレッドで `read_dir` しない。不達の UNC でも固まらない）、応答 ID が古ければ捨てる。対象はディレクトリのみで、システム属性のものは除き、最大 200 件。列挙結果は同じ親の間だけメモリに持ち、ウィンドウを開くたびに捨てる。FR-9.4（打鍵では列挙しない）とは `Tab` の明示操作に限る点で両立する
- **FR-9.26** プレフィックス無しの通常入力でフォルダ候補（実パスの `OpenFolder`）を選んで `Tab` を押すと、検索欄を `<そのフォルダ>\` に置き換え、直下のサブディレクトリを FR-9.25 のパス閲覧として出す。現在のフォルダ自身を開く候補（FR-9.24）は先頭に残り、`Enter` で選択中のサブフォルダを開く。閲覧中の `Tab` は FR-9.25 の補完で、`Shift+Tab` で 1 階層上へ戻る。`ps ` / `ed ` / `cc ` などプレフィックスモードと、フォルダ以外の候補（ウィンドウ・URL 等）では `Tab` は何もしない。新しい `Action` は増やさず、潜った先は使用履歴に記録しない

#### 内部コマンド

- **FR-9.20** waypoint 自身の設定画面 (`waypoint-settings.exe`) を Quick Launch から開ける。プレフィックスモードを新設せず、通常入力の検索対象に固定の内部コマンド候補として 1 件だけ載せる（`Settings` / breadcrumb `Open waypoint settings`）。トレイアイコンの右クリックメニューが唯一の導線だと、ポップアップランチャー廃止後に発見しづらいため。候補は config の項目や外部データに依存しない静的な 1 件で、インデックス構築時の I/O もキー入力時のプロセス起動も伴わない。選択すると常駐部がトレイメニューの "Settings..." と同じ経路で設定画面プロセスを起動する。永続化の対象ではないため、お気に入り昇格（FR-9.8.1）と使用頻度履歴の記録対象からは外す
- **FR-9.22** waypoint の機能一覧を HTML で検索できる Help ページを、トレイの右クリックメニューと Quick Launch の通常入力の両方から開ける。Quick Launch 側は FR-9.20 の Settings と同じ形で、通常検索に固定の内部コマンド候補を 1 件だけ載せる（`Help` / breadcrumb `Open waypoint help`）。ページ本体は `exe と同じディレクトリ\help\index.html` の静的 HTML（サーバー・ビルドツールを持たず、クライアント側 JS でタイトル・プレフィックス・ショートカットキーを対象にインクリメンタル検索する）で、`ShellExecuteW` で既定ブラウザに開く。config や外部データに依存しないため、インデックス構築時の I/O もキー入力時の外部アクセスも伴わない。永続化の対象ではないため、お気に入り昇格（FR-9.8.1）と使用頻度履歴の記録対象からは外す

## 05. データモデル

設定ファイルは単一の JSON。Quick Launch の候補グループは入れ子の配列で表現し、参照や ID を持たせない。手で読み書きできることを優先する。

```json
{
  "version": 1,

  "variables": {
    "Proj": "D:\\work\\projects",
    "Share": "\\\\fileserver\\team\\dev"
  },

  "settings": {
    "quickLaunch": {
      "hotkey": "Alt+Space",
      "includeRecentFolders": true,
      "includeFrequentFolders": true,
      "includeOpenWindows": true,
      "includeBookmarks": true,
      "includeBrowserHistory": true,
      "includeApps": true,
      "azureDevOps": {
        "enabled": true,
        "projects": []
      },
      "includeEverything": true,
      "searchPaths": false,
      "editorCommand": "code",
      "visibleResults": 12,
      "monitor": "primary"
    },
    "startWithWindows": false
  },

  "items": [
    {
      "type": "folder",
      "name": "現在のプロジェクト",
      "path": "{Proj}\\waypoint",
      "open": "reuse",
      "showBranch": true
    },
    { "type": "separator", "name": "開発" },
    {
      "type": "submenu",
      "name": "ビルド出力",
      "items": [
        { "type": "folder", "name": "Debug",   "path": "{Proj}\\waypoint\\target\\debug" },
        { "type": "folder", "name": "Release", "path": "{Proj}\\waypoint\\target\\release" }
      ]
    },
    {
      "type": "specialFolder",
      "name": "ダウンロード",
      "knownFolder": "Downloads"
    }
  ]
}
```

上の JSON の登録項目は Quick Launch の候補として検索される。`submenu` は候補名にグループ名を付与し、`separator` は検索対象にしない。

```
現在のプロジェクト
ビルド出力 / Debug
ビルド出力 / Release
ダウンロード
```

### フィールド定義

| フィールド | 必須 | 内容 |
|---|---|---|
| `type` | 必須 | `folder` / `file` / `specialFolder` / `submenu` / `separator` |
| `name` | 必須 | Quick Launch に表示する文字列。`separator` では省略可 |
| `path` | `folder` / `file` | 絶対パス。変数を含んでよい |
| `knownFolder` | `specialFolder` のみ | 既知フォルダの識別名。`Downloads`、`Desktop` など |
| `items` | `submenu` のみ | 子項目の配列 |
| `open` | 任意 | `folder` / `specialFolder` のみ。`newWindow`（既定）または `reuse` |
| `icon` | 任意 | `folder` / `file`。アイコンファイルのパス。省略時はシステム既定 |
| `showBranch` | 任意 | `folder` / `submenu`。真のとき Git ブランチ名を Quick Launch の候補行の右端に表示する。`submenu` では配下の全 `folder` に継承される。既定は偽 |

## 06. 非機能要件

| 項目 | 目標値 | 備考 |
|---|---|---|
| Quick Launch 表示遅延 | 50ms 以内 | ホットキーまたはトレイ操作から描画完了まで。体感で最も重要な指標 |
| 常駐メモリ | 60MB 以下 | ワーキングセット。常時起動のため |
| 起動時間 | 1.5 秒以内 | Windows ログオンからトレイ常駐まで |
| DPI 対応 | Per-Monitor V2 | 複数モニタでスケーリングが異なる環境を想定する |
| ダークモード | 対応 | Quick Launch と管理画面はシステムテーマに従う |
| 長いパス | 260 文字超に対応 | ネットワークパスで到達しうる |
| ログ | ファイル出力 | `%APPDATA%\waypoint\log.txt`。起動・設定読込・エラーのみ記録 |

## 07. 技術構成

常駐部と Quick Launch は **Rust + `windows` crate**、管理画面は **.NET 8 + WPF** で実装する。管理画面は必要時のみ別プロセスで起動し、保存後は `PostMessage` で常駐部へ設定の再読み込みを通知する。

### 構成

| 層 | 実装 | 備考 |
|---|---|---|
| Quick Launch | 独自 Win32 ウィンドウ | 検索・選択・描画を一つのウィンドウで完結する |
| Win32 バインディング | `windows` crate 0.62 | 必要な feature のみ有効化 |
| ホットキー | `RegisterHotKey` + メッセージ専用ウィンドウ | `HWND_MESSAGE` の子で `WM_HOTKEY` を受ける |
| エクスプローラー操作 | `IShellWindows` (COM) | ウィンドウ列挙と `Navigate`。`COINIT_APARTMENTTHREADED` で初期化 |
| 既知フォルダ解決 | `SHGetKnownFolderPath` | GUID 表を持つ |
| アイコン取得 | `SHGetFileInfo` | 取得結果をパス単位でキャッシュする |
| トレイアイコン | `Shell_NotifyIcon` | 実装済み (`src/tray.rs`) |
| 管理画面 | .NET 8 / WPF | 別プロセスで必要時のみ起動。常駐部とは設定ファイルと `PostMessage` で連携 |
| 設定の入出力 | `serde` + `serde_json` | `preserve_order` で項目順を保つ |
| 二重起動抑止 | 名前付き Mutex | 既存プロセスへの通知は `PostMessage` |

## 10. 将来拡張

v1.0 完了後、P4 の使用記録をもとに着手可否を判断する。着手する場合は本仕様書を更新してから始める。

| 候補 | 着手を判断する条件 |
|---|---|
| ファイルダイアログ内のフォルダ切替 | 保存ダイアログでの手動フォルダ移動が、実測で 1 日 10 回を超えている場合 |
| ライブフォルダ | プロジェクトのサブフォルダを個別登録する運用が破綻した場合。フィルタは拡張子指定のみに限定する |

| コマンドラインからのメニュー呼び出し | 他のスクリプトから呼びたい具体的な場面が生じた場合 |
