# waypoint 仕様書

| | |
|---|---|
| 版 | v0.2 (draft) |
| 状態 | 開発初期 / 土台のみ |
| 対象 | Windows 10 22H2 以降 |

Windows 向けの常駐型ランチャー。Quick Launch で登録した場所やアプリを検索して一手で移動・起動する。Quick Access Popup の中核機能をベースに、フォルダ移動を主軸としつつアプリ起動・ブックマーク検索まで扱う汎用ランチャーとして再構成したもの。

> **v0.1 からの変更**: 実装言語を C#/WPF から **Rust + windows crate** に変更（07 章）。アプリ名を FolderPop から **waypoint** に変更。

---

## 01. 概要

### 目的

日常的に使う場所・ウィンドウ・アプリ・情報への到達コストをゼロに近づける。デスクトップのショートカット、エクスプローラーのクイックアクセス、タスクバーのピン留め、ブラウザのブックマーク、Alt+Tab、スタートメニュー検索に分散している導線を、Quick Launch に集約する。Windows 向け汎用ランチャーとして、検索できる対象の広さと動作の速さの両方で他のランチャー（Flow Launcher、PowerToys Run 等）に劣らないことを目指す。

### 想定ユーザー

作成者本人のみ。複数プロジェクトのソースツリー、ビルド出力、ログ、ドキュメントの各フォルダを一日に何十回も行き来する開発者。設定ファイルを直接編集することに抵抗がなく、GUI とテキストの両方から設定を触りたい。

### 成功の判定

本人が 2 週間連続で毎日使い、既存のショートカット群を消しても不便を感じないこと。それ以外の指標（ユーザー数、配布、ストア公開）は追わない。

### 非目標

- テキスト展開・ホットストリングは対象外。キーストローク送出のミニ言語は実装しない
- 自前のファイルインデックスは作らない。ファイルシステムの全件走査は行わない（アプリ起動はスタートメニュー / インストール済みショートカットの列挙に限る）。PC 全体のファイル名検索は Everything（別プロセス）へ問い合わせるだけで、waypoint 自身は何も索引化しない
- 第三者への配布を前提としない。自動更新、多言語化は作らない
- ただし**インストーラ (MSI) は作る**。自分の複数マシンへ同じ構成で入れ直すため（02 章参照）
- ファイラー固有の操作 API には対応しない。新規表示は Windows の既定フォルダーハンドラーに従う

## 02. スコープ

Quick Access Popup の全機能を分解し、本プロジェクトでの扱いを確定させる。**採用** は v1.0 に含む。**保留** は v1.0 の後に再検討する。**除外** は作らないと決めたもので、再検討もしない。

| 機能軸 | 判定 | 理由 |
|---|---|---|
| ポップアップメニュー表示 | 除外 | Quick Launch へ一本化するため |
| フォルダ型お気に入り | **採用** | 本体 |
| 特殊フォルダ（既知フォルダ） | **採用** | KNOWNFOLDERID の対応表を持つだけで済む。費用対効果が高い |
| My Special Folders | **採用** | よく使う既知フォルダと Windows シェル名前空間への固定入口を QAP と同じ構成で提供する |
| サブメニュー・区切り・アイコン | **採用** | 登録数が 20 を超えた時点で階層化が必須になる |
| 変数展開（環境変数・ユーザー変数） | **採用** | ネットワークパスとユーザープロファイル配下のパスが長く、実質必須 |
| 管理 GUI | **採用** | 本人の希望により第 1 版から含める。工数の最大項目 |
| フォルダ構造の一括取り込み | **採用** | 起点フォルダと探索深度からメニュー階層を一度生成し、登録作業を短縮する |
| ライブフォルダ（動的展開） | 保留 | プロジェクトフォルダ配下の一覧に効くが、フィルタ仕様が膨らみやすい |
| ファイルダイアログ内のフォルダ切替 | 保留 | 価値は高いがダイアログ判定が泥臭い。エクスプローラー対応が安定してから |
| Quick Launch（クイック検索） | **採用** | 本体。名前を入力してキーボードだけで目的のフォルダやアプリを開く |
| In the Works（Recent / Frequent のフォルダ・ファイル） | **採用** | Windows の Recent Items をローカル集計し、作業中の項目へ素早く戻るために使う |
| Current Windows | **採用** | 現在開いている Explorer とアプリのウィンドウへ切り替える |
| ブラウザブックマーク検索 | **採用** | Quick Launch で `b ` に続けて入力すると Chrome / Edge のブックマークだけを検索し、選択すると既定ブラウザで開く。フォルダ移動ではないが Quick Launch の検索窓を流用でき、追加コストが小さい |
| ブラウザ履歴検索 | **採用** | Quick Launch で `h ` に続けて入力すると Chrome / Edge の履歴だけを検索し、選択すると既定ブラウザで開く。履歴 DB はインデックス更新時に読むだけで、キー入力・表示の経路ではメモリ上の候補だけを検索する |
| 現在のブラウザタブ検索 | **採用** | Chrome / Edge 拡張が現在のタブ一覧を Native Messaging で常駐部へ渡し、Quick Launch で `t ` に続けて検索・前面化する。Native Messaging host の登録は waypoint 起動時に自動で行う。拡張未導入時は 0 件とし、タブ情報はメモリだけに置く |
| アプリ起動（インストール済みアプリの検索・起動） | **採用** | スタートメニューのショートカット (`.lnk`) を列挙し、Quick Launch で `a ` に続けて入力すると検索できる。フォルダ・ブックマークと同じ「検索して一手で開く」体験に揃える。ファイルシステム全体のインデックス化はしない |
| Everything 連携（PC 全体のファイル名検索） | **採用** | Quick Launch で `f ` に続けて入力すると、常駐中の Everything へ IPC で問い合わせて結果を出す。waypoint 自身は索引を持たず、Everything が未インストール・未起動なら 0 件を返すだけでエラーにしない |
| Azure DevOps 検索 | **採用** | Quick Launch で `az ` に続けて入力すると、設定したプロジェクトの PR・パイプライン・Work Item を検索する。PAT は Windows Credential Manager にのみ保存し、PR・パイプラインは SQLite キャッシュ、Work Item は非同期の API 検索を使う |
| ターミナルでフォルダを開く | **採用** | Quick Launch で `ps ` に続けて入力すると、既存のフォルダ候補（config 登録・Recent/Frequent）だけを検索し、選択すると Windows Terminal + PowerShell 7 (`wt.exe -d <path> pwsh`) でそのフォルダを開く。新規データソースを増やさず既存インデックスに絞り込みを乗せるだけなので追加コストが小さい |
| PowerShell PROFILE の関数・エイリアス実行 | **採用** | Quick Launch で `pf ` に続けて入力すると、`$PROFILE` が定義した関数・エイリアスだけを検索し、選択すると Windows Terminal + PowerShell 7 で即実行する。PowerToys Run 等にある「コマンド実行」相当を、自分の PROFILE 資産で使えるようにする |
| Git ブランチ名の表示 | **採用** | 同一リポジトリの複数ワークツリーを使い分けるため、ジャンプ先の判断材料として必要。項目ごとのオプトインに限定し、表示経路では `.git/HEAD` のキャッシュのみ参照する |
| 設定のマシン間持ち出し（`shared.json`） | **採用** | 複数マシンへ同じ構成で入れ直す用途（本表の MSI 採用理由と同じ動機）。`items`（パス）は環境依存だがトリガー設定・Quick Launch のフラグ・Azure DevOps プロジェクト一覧は環境非依存で、実際に持ち出したい設定であることを実機の `config.json` で確認済み。保存時に `settings` だけを複製書き出しし、Git やクラウド同期フォルダ経由の手動運用を前提とする（waypoint 自身は Git 操作をしない）。除外済みの「共有メニュー / 設定同期」は複数ユーザー間の同期衝突を指しており、これとは主体が異なる |
| 電卓（式を Quick Launch で即計算） | 保留 | 他のランチャーで評価の高い機能。式パーサの実装コストと精度（浮動小数点・単位換算の扱い）を詰めてから着手する |
| システムコマンド（シャットダウン・スリープ・ロック等） | 保留 | Win32 呼び出しのみで実装コストは小さいが、意図しない実行を防ぐ確認導線の要否を先に決める |
| クリップボード履歴 | 保留 | 価値は高いが `WM_CLIPBOARDUPDATE` の常時監視が常駐コストになるため、トリガーパスに影響しない設計を先に詰める |
| Reopen a Folder | 除外 | Current Windows と役割が重複し、ファイルダイアログ内のフォルダ切替も v1.0 の対象外 |
| スニペット / ホットストリング | 除外 | キーストローク送出のミニ言語を実装することになる。用途が無関係 |
| プレースホルダ（動的値挿入） | 除外 | 実質的に式評価エンジン。変数展開で代替する |
| グループ一括起動 | 除外 | 起動遅延やエラー時中断の制御が必要になり、単発起動を素早く行うという設計と衝突する。まとめて開きたい場合は個別に呼べば足りる |
| 共有メニュー / 設定同期 | 除外 | 単一ユーザーのため同期衝突の概念が存在しない |
| FTP サイト | 除外 | 用途なし |
| 電源操作・ウィンドウ管理 | 除外 | ランチャーの責務ではない |
| 他ファイラー固有連携（DOpus / TC） | 除外 | 各ファイラーの外部インターフェース仕様は扱わない。OS の既定フォルダーハンドラーは使用する |
| インストーラ (MSI) | **採用** | 常駐アプリなので置き場所とスタートメニュー登録を毎回手作業したくない。自分の複数マシンへ同じ構成で入れ直すために使う |
| 自動更新・多言語 | 除外 | 配布しないため不要。更新は MSI の再インストールで足りる |

> **スコープを守るための約束**
>
> 「除外」に入れた項目は、実装中に思いついても v1.0 では着手しない。追加したくなった場合は本表を書き換えてから着手する。**仕様書を更新せずに機能を足すことを禁止する。** この一文が本仕様書の存在意義である。

## 03. 用語

| 用語 | 定義 |
|---|---|
| 項目 | Quick Launch の候補元となる設定項目。フォルダ・特殊フォルダ・サブメニュー・区切りのいずれかの型を持つ |
| メニュー | 設定項目を分類する入れ子のリスト。Quick Launch では候補のパンくずとして使う |
| トリガー | Quick Launch を表示させる入力操作。グローバルホットキー、トレイアイコンの左クリック、または二重起動 |
| 元ウィンドウ | Quick Launch を開いた時点で最前面だったウィンドウ。`reuse` の対象を決めるために保持する |
| 設定ファイル | 項目定義とアプリ設定を保持する JSON ファイル。単一ファイルとする |
| 常駐部 | トレイに常駐しトリガーを待ち受けるプロセス |
| 管理画面 | 項目を編集するウィンドウ。必要時のみ生成する |

## 04. 機能要件

### FR-3 項目の型

| 型 | 保持する情報 | 選択時の動作 |
|---|---|---|
| `folder` | 表示名、パス、開き方、ブランチ表示の可否 | 指定パスを既定のフォルダーハンドラーで開く |
| `file` | 表示名、パス | 指定ファイルを既定の関連付けアプリで開く（`newWindow`/`reuse` の概念を持たない） |
| `specialFolder` | 表示名、既知フォルダ ID | 解決したパスを既定のフォルダーハンドラーで開く |
| `submenu` | 表示名、子項目の配列 | Quick Launch の候補にパンくずを付ける |
| `separator` | 表示名（省略可） | Quick Launch の候補にはしない |

### FR-4 フォルダを開く動作

- **FR-4.1** 開き方は `newWindow`（既定のフォルダーハンドラーで開く）と `reuse`（元ウィンドウのフォルダを変更）の 2 種。既定は `newWindow`
- **FR-4.2** `reuse` は元ウィンドウがエクスプローラーである場合のみ有効。それ以外は `newWindow` にフォールバックする
- **FR-4.3** `Shift` を押しながら選択した場合、項目の設定に関わらず `newWindow` で開く
- **FR-4.4** 開いたウィンドウは、トリガーが発生したモニタ上に配置する

### FR-5 変数展開

- **FR-5.1** パス中の `%NAME%` を Windows 環境変数として展開する
- **FR-5.2** パス中の `{NAME}` を設定ファイル内のユーザー変数として展開する
- **FR-5.3** 展開は項目の選択時ではなく設定の読み込み時に一度だけ行い、結果をメモリに保持する
- **FR-5.4** 解決できない変数を含む項目は起動時のログに記録し、Quick Launch の候補には含めない。アプリは停止しない

### FR-6 管理画面

- **FR-6.1** エクスプローラー型のレイアウトで、左に候補グループのツリー、右に選択中グループの項目一覧を表示する。上部のツールバーに作成・編集・整理の操作を機能グループ別（Add / Edit・Remove・Duplicate / Copy・Paste・Move...）に並べ、変数と Quick Launch の設定を別タブにまとめる
- **FR-6.2** 項目の追加・編集・削除・複製ができる
- **FR-6.3** 一覧内で項目の順序を上下ボタンで変更できる。加えて、行をドラッグして任意の位置へ落とすことでも並べ替えられる。ドラッグ中は挿入位置を線で示す
- **FR-6.4** フォルダ選択ダイアログ（`folder`）またはファイル選択ダイアログ（`file`）からパスを指定できる
- **FR-6.5** エクスプローラーからのドラッグ＆ドロップで項目を追加できる。フォルダは `folder`、ファイルは `file` として追加する
- **FR-6.6** 保存ボタンで設定ファイルへ書き出し、常駐部へ再読み込みを通知して Quick Launch のインデックスを再構築する。保存前に閉じようとした場合は確認する
- **FR-6.7** ユーザー変数を編集する画面を持つ
- **FR-6.8** Quick Launch のホットキーを編集する設定画面を持つ。保存は設定ファイルへの保存と常駐部への再読み込みまで完了させる
- **FR-6.8.1** ホットキーは文字列の直接入力に加え、実際のキー入力から設定できる。記録中は打鍵を OS へ渡さず、`Win+W` のようにシステムが予約している組み合わせもそのまま記録できる。`Esc` で取り消す
- **FR-6.9** 起点フォルダと探索深度（0〜10）を指定し、サブフォルダ構造を候補グループとして一括取り込みできる。取り込み前に名称変更と除外ができ、確定後は通常の項目編集・並べ替えを利用できる
- **FR-6.10** 取り込みは確定時の一度だけ行い、元フォルダとの自動同期は行わない
- **FR-6.11** 一覧の行は Ctrl+クリック（トグル）・Shift+クリックまたは Shift+矢印（範囲選択）・Ctrl+A（全選択）で複数選択できる。削除・上下移動・複製・コピー＆ペーストは選択中の全項目へまとめて適用される。バラバラな選択で上下移動する場合、端に達する項目が一つでもあれば全体を動かさない
- **FR-6.12** 複数選択時、Edit は共有プロパティ一括編集ダイアログを開く。Open mode（New window / Reuse / 変更しない）と Show Git branch name（On / Off / 変更しない）の 3 状態を選択項目全体へ適用する
- **FR-6.13** 選択中の項目（単一・複数とも）は「Move...」で別の候補グループ（サブメニュー）の末尾へまとめて移動できる。移動先が選択項目自身の配下を指す場合は何もしない
- **FR-6.14** 右ペインに全グループ横断の検索ボックスを持つ（`Ctrl+F` でフォーカス、`Esc` でクリア）。名前またはパス/ターゲットへの部分一致（大小文字を区別しない）で全グループを再帰的に検索し、ヒットした項目の種別・所属グループ・詳細を一覧表示する。行を選ぶと該当グループへ切り替えて選択状態にし、検索を閉じて通常表示に戻る。検索中は一覧の編集操作（追加・編集・削除・並べ替え等）を無効化する
- **FR-6.15** 左の候補グループツリーと「Move...」の移動先選択には、それぞれ名前の部分一致で絞り込むフィルター欄を持つ。一致したグループだけでなく、そこへ至る祖先グループも表示に残す

> 管理画面は .NET 8 + WPF の別プロセスとして実装する。必要時だけ起動し、常駐部と Quick Launch の起動時間・メモリ・メッセージループへ影響させない。

### FR-7 設定の永続化

- **FR-7.1** 設定は `%APPDATA%\waypoint\config.json` に保存する
- **FR-7.2** 起動時に設定ファイルが無い場合、既定の設定を生成する
- **FR-7.3** 保存時、既存ファイルを退避してから書き込む（temp に書いて置換する原子的更新）
- **FR-7.4** JSON の解析に失敗した場合、空の Quick Launch 候補で起動し、トレイ通知でエラーを知らせる。設定ファイルは上書きしない
- **FR-7.5** 手編集を想定し、インデント 2 桁・日本語は非エスケープ・**項目順を保存で入れ替えない**（`serde_json` の `preserve_order`）
- **FR-7.6** Recent Items の利用回数は `%APPDATA%\waypoint\history.json` にローカル保存する。外部へ送信しない
- **FR-7.7** 設定保存時、環境非依存な `settings`（Quick Launch・Azure DevOps プロジェクト一覧）を `%APPDATA%\waypoint\shared.json` へも複製書き出しする。起動時、`shared.json` が存在すれば `config.json` 読み込み後にその `settings` で上書きする（`shared.json` が同期の正とする）。`items`・`variables` は環境依存のため対象外。ユーザーが `shared.json` を Git やクラウド同期フォルダへ置くことで複数マシン間の設定持ち出しに使う。waypoint 自身は同期処理（Git 操作・アップロード等）を行わない

### FR-8 常駐とライフサイクル

- **FR-8.1** 起動時にタスクトレイへ常駐する。ウィンドウは表示しない
- **FR-8.2** トレイアイコンの右クリックメニューに「設定を開く」「設定を再読み込み」「終了」を持つ
- **FR-8.3** 二重起動を抑止する。二つ目のプロセスは既存プロセスにメニュー表示を要求して終了する
- **FR-8.4** Windows 起動時の自動実行を設定で切り替えられる

### FR-9 Quick Launch

- **FR-9.1** 設定可能なグローバルホットキー（既定 `Alt+Space`）で検索画面を開く。`RegisterHotKey` が失敗した場合は低レベルキーボードフックで同じキーを横取りする
- **FR-9.2** 登録済みの `folder` / `file` / `specialFolder`、設定で有効にした Recent / Frequent Folders、Current Windows、ブックマーク、アプリを、プレフィックスなしの通常入力でも横断して検索対象にする。ブラウザ履歴（FR-9.17）は件数が多くキー入力ごとの全件走査が体感の重さに直結するため対象外とし、`h ` のプレフィックスモード限定のままとする。Everything（FR-9.16）と Azure DevOps（FR-9.18）は外部 IPC / API / DB を伴うため対象外とし、`f ` / `az ` のプレフィックスモード限定のままとする
- **FR-9.3** 項目名と所属サブメニューのパンくずを、大文字小文字を区別しない部分一致で検索する。空白区切りの語は AND 条件とする
- **FR-9.4** パス検索は設定で有効化できる。検索中にパスの存在確認やネットワークアクセスを行わない
- **FR-9.5** 名前の完全一致、先頭一致、単語境界一致、部分一致、パンくず一致、パス一致の順に候補を並べる。直接一致しない場合は、文字順・連続性・単語境界を考慮した Fuzzy 検索で名前、パンくず、パス（FR-9.4 が有効な場合）を照合する。同点ではメニュー順を保つ
- **FR-9.6** 候補には名前、パンくず、解決済みパスを表示し、同名項目を判別できるようにする。`folder` 候補は `showBranch` 継承規則で Git ブランチ名を項目名の後ろに付す。取得はインデックス構築時にまとめて行い、検索・描画の経路では `.git` を読まない
- **FR-9.7** `Up` / `Down` / `Home` / `End` / `PageUp` / `PageDown` で候補を移動し、`Enter` で実行、`Esc` またはフォーカス喪失で閉じる
- **FR-9.8** `Shift+Enter` は常に `newWindow`、`Ctrl+Enter` は常に `reuse` として開く。開き方を持たない候補（Current Windows・ブックマーク・アプリ）はこの修飾を無視する。ただし `az pr` / `az wit` / `az pipeline` の入力中は FR-9.18 の Live 検索を優先する
- **FR-9.8.1** `Ctrl+Shift+Enter` で選択中の候補を設定のルートメニュー末尾へ追加登録する（お気に入り昇格）。対象はフォルダ・ファイル・Everything の検索結果・アプリのみで、永続化できないウィンドウ（Current Windows）と URL（ブックマーク。`b ` で既に検索できるため）は無音で無視する。同じパスを持つ項目がメニュー階層のどこかに既にあれば（大文字小文字を区別せず）追加しない。ウィンドウは閉じず、続けて他の候補も登録できる
- **FR-9.8.2** リストにフォーカスがある状態での `Ctrl+C` は、選択中候補のパスをクリップボードへコピーする。検索窓 (Edit) にフォーカスがある間は通常のテキストコピーを優先し、この動作を割り込ませない
- **FR-9.8.3** `Ctrl+E` は選択中候補をエクスプローラーで開き、対象自体を選択状態にする（`explorer.exe /select,`）。ウィンドウは閉じる
- **FR-9.9** 検索インデックスは起動時、設定再読み込み時、動的メニュー更新後に構築する。キー入力時はメモリ上の検索だけを行う
- **FR-9.10** 検索画面は常駐プロセス内の標準 Win32 コントロールで実装し、管理画面プロセスを起動しない
- **FR-9.11** 検索画面は黒を基調とし、`Segoe UI Variable Text`、Windows 11 の角丸・ダークタイトルバー、青系の選択色を使う。未対応環境では通常の Win32 表示へフォールバックする
- **FR-9.12** 候補はフォルダーアイコン、名前、パンくずとパスの 2 段を高密度に描画し、DPI に応じてフォント・余白・行高を拡縮する。表示件数は 12〜24 件、既定は 12 件とする
- **FR-9.13** ブックマークは FR-9.2 により通常入力でも検索対象になる。入力が `b ` (半角スペース込み) で始まる間はブックマークだけに絞り込み、残りの文字列で検索する。選択すると既定ブラウザで URL を開く。ブックマーク取り込みは設定で無効化できる
- **FR-9.14** アプリは FR-9.2 により通常入力でも検索対象になる。入力が `a ` (半角スペース込み) で始まる間はスタートメニューのショートカット (`.lnk`) だけに絞り込み、残りの文字列で検索する。選択すると対象アプリを起動する。アプリ検索は設定で無効化できる
- **FR-9.15** Current Windows は FR-9.2 により通常入力でも検索対象になる。入力が `w ` (半角スペース込み) で始まる間は Current Windows だけに絞り込み、残りの文字列で検索する。選択すると対象ウィンドウへ切り替える。Current Windows の取り込みは設定で無効化できる。検索はウィンドウタイトルに加え所有プロセスの実行ファイル名にもマッチする（`w chrome` のようにタイトルへアプリ名が出ないウィンドウも見つけられる）
- **FR-9.15.1** 入力が `ps ` (半角スペース込み) で始まる間は、フォルダを指すパスを持つ既存候補（config 登録の folder/specialFolder、Recent/Frequent Folders）だけに絞り込み、残りの文字列で検索する。Everything 結果は対象外（別インデックス系統で、混ぜると実装が複雑になるため）。新規のデータソースは持たず、通常検索と同じインデックスへの絞り込みフィルタとして実装する。選択すると `wt.exe -d <path> pwsh` で Windows Terminal 上に PowerShell 7 を明示的に指定して起動する（Windows Terminal の既定プロファイル設定には依存しない）。`wt.exe` または `pwsh` が見つからない場合は `powershell.exe -NoExit -WorkingDirectory <path>`（Windows 標準の PowerShell 5.1）にフォールバックする。開き方（newWindow/reuse）の概念は持たない
- **FR-9.16** 入力が `f ` (半角スペース込み) で始まる間は通常の検索対象を隠し、常駐中の Everything へ IPC (`WM_COPYDATA`) で問い合わせて結果をそのまま並べる。Enter でエクスプローラーの既定ハンドラーで開く。Everything が見つからない・応答しない場合は 0 件を返し、エラー表示はしない。Everything 連携は設定で無効化できる（既定オフ。全ファイル検索は個人の意図的な操作でのみ有効にする）
- **FR-9.16.1** `f ` モード中、`Alt+C` (Match Case) / `Alt+W` (Match Whole Word) / `Alt+R` (Regex) で Everything IPC の検索フラグをトグルできる。トグルすると同じクエリを新しいフラグで即座に再送する。アクティブなフラグは検索窓の `FILES` バッジの左に短いピルで表示する。フラグの状態は `f ` モードを抜けても保持し、次に `f ` へ入ったときも引き継ぐ（プロセス内メモリのみ、設定ファイルへは保存しない）
- **FR-9.17** 入力が `h ` (半角スペース込み) で始まる間は通常の検索対象を隠し、Chrome / Edge の既定プロファイルの閲覧履歴だけを残りの文字列で検索する。選択すると既定ブラウザで URL を開く。履歴取り込みは設定で無効化でき、URL も検索対象にする。履歴 DB の読取は FR-9.9 のインデックス更新時に限定し、キー入力・表示の経路では行わない
- **FR-9.17.1** 入力が `t ` (半角スペース込み) で始まる間は通常の検索対象を隠し、Chrome / Edge の現在開いているタブだけをタイトルと URL で検索する。選択すると、拡張経由で対象ブラウザのウィンドウとタブを前面化する。タブのタイトル・URL・ID はメモリだけに置き、設定・履歴・ログへ保存しない。Native Messaging host の manifest と Chrome / Edge のユーザー登録は waypoint 起動時に更新する。初回の対話的 MSI インストール完了後は、拡張を読み込むローカル案内ページを自動で開く。拡張またはブラウザが未起動なら 0 件を返す。タブ変更時のスナップショット更新だけを受け、Quick Launch の表示・キー入力時にブラウザへ同期問い合わせを行わない
- **FR-9.18** 入力が `az ` (半角スペース込み) で始まる間は通常の検索対象を隠し、設定済み Azure DevOps プロジェクトの候補だけを検索する。`az ` の直後は `az pr` / `az wit` / `az pipeline` / `az project` / `az optimize` などのコマンド候補を表示する。`pr` / `wit` / `pipeline` / `project` は検索を伴うサブコマンドなので、選んでも実行せず検索欄を補完するだけ（続けて絞り込む）。`optimize` は検索対象を持たない単一アクションのコマンドなので、一覧から選んだ時点で即座に実行する（`az optimize` とフルタイプしてから確定候補を選ぶのと同じ 1 手で完了させ、「補完してからもう一度選ぶ」二度手間を発生させない）。サブコマンドの後ろには属性トークンを空白区切りで順不同・任意個数並べられる。`az pr`（`prs`）に続けられる属性トークンは `active` / `completed`（`complete`）/ `abandoned`（`abandon`）/ `all`（状態、省略時 all）、`mine`（`me`、自分が作成またはレビュー担当）、`live`（Live 検索用の互換トークン）で、`az pr active mine` のように組み合わせられる。`az wit` でも `live` 属性トークンを使えるが、入力だけでは API を呼ばず `Ctrl+Enter` で実行する。`az pipeline`（`pipelines` / `pipe` / `build` / `builds`）に続けられる属性トークンは `failed`（`fail`）/ `definition`（`definitions` / `def`）/ `all`（省略時 all）。既知の属性トークンが尽きた時点から先を検索語として扱う（例: `az pr active mine Hoge` は状態 Active・自分の PR に絞って `Hoge` を検索）。`az pr` / `az wit` / `az pipeline` の入力中に `Ctrl+Enter` を押すと、検索語が空でも現在の属性条件で Live 検索を実行する。PR の状態を省略した Live 検索は API 負荷を抑えるため Active のみを取得し、3 状態すべてを取得する場合は `all` を明示する。Live 検索は同時に 1 件だけ実行し、同一条件の完了後 2 秒以内の再実行も無視する。操作ヒントは `az` モード中の検索バーに表示する。通常の Enter はキャッシュ候補の選択・実行に使う。`az project`（`projects`）はプロジェクトを検索する。候補を選ぶと対応する Azure DevOps の Web ページを開く。タイトル検索では入力した語句がその順序で連続する候補を最優先し、次に全語がタイトルへ一致する候補を並べる。4 文字以上の英数字語は挿入・削除・置換・隣接文字の入れ替えが 1 文字だけのタイプミスも一致として扱う
- **FR-9.18.1** `az wit `（`wi` / `workitems`）と `az pr`（`prs`）の Active な候補は、waypoint と DevDeck（別リポジトリの Azure DevOps ダッシュボードアプリ）のどちらの内部スキーマにも属さない中立な共有キャッシュ（`%APPDATA%\\AzDoSharedCache\\cache.db`）を参照する。両アプリが同じ組織を独立にポーリングして API 呼び出しが重複するのを避けるため、この共有キャッシュが直近更新済み（自分でも DevDeck でも）なら waypoint は自分の API 呼び出しをスキップし、古ければ取得したうえで共有キャッシュにも書き込む（`api.rs::refresh_project`）。is_mine の判定は共有キャッシュの `created_by_id` / レビュアー一覧を自分の認証ユーザー ID（`identity` テーブルに事前解決済み、キー入力経路ではネットワークに触れない）と突き合わせて waypoint 側で計算する。`az wit` のローカルキャッシュが 0 件なら Live 検索候補を表示するが、API は候補の Enter または `Ctrl+Enter` の明示操作でのみ非同期に問い合わせ、ライブ検索結果は永続化しない。PR の Completed/Abandoned 履歴（過去 90 日ぶん、DevDeck の対象外）は引き続き waypoint 自身の `%APPDATA%\\waypoint\\azure_devops.db` にキャッシュし、起動時・設定再読み込み時・12 時間おきにバックグラウンド同期する。Pipeline は永続キャッシュを持たず、Live 検索候補の Enter または `Ctrl+Enter` の明示操作で問い合わせる
- **FR-9.18.2** Azure DevOps の PAT は設定ファイルへ保存せず、組織ごとに Windows Credential Manager へ保存する。設定画面の専用プロジェクト選択画面では PAT 保存後に組織のプロジェクト一覧を取得し、文字列で絞り込みながら複数の監視対象をチェックで選べる。一覧でチェックした行を選ぶと詳細パネルが開き、別名・優先度・同期スコープ（PR / Pipeline / Work Item）・興味のある Area Path を GUI 上で編集できる。Area Path は Azure DevOps の Area 階層 API から取得したツリーをチェックボックスで選ぶ（検索フィルタ付き）。テキスト DSL を手打ちする経路は持たない。「Suggest from my assigned work items」ボタンを押すと、選択中プロジェクトで自分に割り当てられた Work Item を WIQL (`[System.AssignedTo] = @Me`) で取得し、その Area Path を件数の多い順に候補として表示する（チェックボックスで選択に追加できる）。ボタンを押すまで API は呼ばない
- **FR-9.18.2.1** `az optimize`（`suggest` / `rank` でも入れる）は Quick Launch から直近アクティビティを基にした最適化を起動する専用コマンド。検索対象を持たず確定候補を 1 件だけ表示し、選ぶと常駐部がバックグラウンドで監視中の全プロジェクトを集計する。設定画面は開かず、ユーザーの選択も求めない。Azure DevOps の Account My Work Recent Activity REST API から、自分の直近90日間の Work Item を取得し、プロジェクトごとに Iteration Path を件数順で集計する。各プロジェクトには最頻の Iteration Path を `interestIterations` として自動保存し、Work Item 検索ではその Iteration 配下に絞る。プロジェクトの `priority` はアクティビティ件数の多い順（同数時は既存 priority 順）に振り直す。アクティビティが取得できない場合や90日内に対象が無い場合は設定を変更せずログへ記録する。REST API で展開されない WIQL の UI マクロには依存しない。実行するまで API は呼ばない
- **FR-9.18.3** waypoint 自身が同期する PR 履歴のキャッシュにはプロジェクト別の最終成功時刻と失敗状態を保持する。設定画面とトレイメニューで鮮度を表示し、手動更新できる（Active PR / Work Item の鮮度は共有キャッシュの `sync_state`（自分か DevDeck、どちらが最後に更新したか）に依存するため、この表示の対象外）。同一の同期要求は重複実行しない。HTTP 429 および 5xx は短いバックオフを伴い再試行し、`Retry-After` 応答ヘッダーがあれば固定バックオフより優先して指定秒数を待つ。失敗時も直前の成功キャッシュを残す
- **FR-9.18.4** `az` 検索は自分が関与する項目を優先する。PR は作成者またはレビュー担当が自分の場合（`is_mine`）、`az` 横断検索および `az pr` 系コマンドのデフォルト表示で他の PR より前に並べる（`mine` 属性トークンによる絞り込みとは独立に適用する）。プロジェクトごとに関心のある Area Path を設定でき（`az wit` の WIQL 検索条件に組み込む）、設定済みなら一致する Work Item だけを対象にする。未設定のプロジェクトはプロジェクト全体を対象にする（従来どおり）
- **FR-9.18.5** 共有キャッシュ（`AzDoSharedCache\cache.db`）は waypoint の可用性を DevDeck 側のスキーマ変更や書き込みタイミングに依存させない設計にする。DB ファイルが開けない、または想定と異なるスキーマでクエリが失敗した場合は、その呼び出しだけを空扱いにして通常表示を継続する（クラッシュしない）。waypoint 自身が保持する接続はクエリ失敗を検知した時点で破棄し、次回呼び出しで新しい接続を開き直す（`shared_cache::with_cached_connection` の healthy フラグ）。共有キャッシュ自体が開けない場合でも、waypoint 自身の PR 履歴キャッシュ（FR-9.18.3）は独立した DB のため引き続き機能する（Active PR / Work Item のみ 0 件表示になる）。DevDeck 側のスキーマ変更で読み取りが恒常的に失敗するようになった場合の切り離し手順は、共有キャッシュの参照 (`mod.rs::cached_candidate_groups` / `shared_cache::open`) を waypoint 自身の非共有キャッシュ実装に戻すことで復旧できる（DevDeck 側の変更を待たずに waypoint 単独で対応可能な設計を維持する）
- **FR-9.19** 入力が `pf ` (半角スペース込み) で始まる間は通常の検索対象を隠し、PowerShell 7 (`pwsh`) の `$PROFILE` が定義した関数・エイリアスだけを、最初の半角スペースまでのトークンで検索する。一覧は waypoint 起動時に非同期のバックグラウンドで一度だけ取得し（`pwsh -NoProfile` のベースラインと通常起動の `Get-Command -CommandType Function,Alias` の差分を取り、モジュールが公開するコマンドと素のエンジン内蔵エイリアスを除外する）、以後はメモリ上のキャッシュだけを検索する。設定画面またはトレイの手動更新までは再取得しない。マッチしたトークンより後ろに続けて入力した文字列は実行時の引数としてそのまま扱い、候補ラベルに `関数名 引数...` の形でその場に反映する。選択（Enter）すると Windows Terminal + PowerShell 7 (`wt.exe <pwsh> -NoExit -Command "<関数名> <引数...>"`) で即実行する。`pwsh` が見つからない場合は 0 件を返し、エラー表示はしない（Windows PowerShell 5.1 へのフォールバックはしない — 対象は pwsh 7 の PROFILE に限る）。実行した組み合わせは引数を含め毎回異なりうるため Recent/Frequent の使用履歴には記録しない。PROFILE の取り込みは設定で無効化できる（既定オン）
- **FR-9.20** waypoint 自身の設定画面 (`waypoint-settings.exe`) を Quick Launch から開ける。プレフィックスモードを新設せず、通常入力の検索対象に固定の内部コマンド候補として 1 件だけ載せる（`Settings` / breadcrumb `Open waypoint settings`）。トレイアイコンの右クリックメニューが唯一の導線だと、ポップアップランチャー廃止後に発見しづらいため。候補は config の項目や外部データに依存しない静的な 1 件で、インデックス構築時の I/O もキー入力時のプロセス起動も伴わない。選択すると常駐部がトレイメニューの "Settings..." と同じ経路で設定画面プロセスを起動する。永続化の対象ではないため、お気に入り昇格（FR-9.8.1）と使用頻度履歴の記録対象からは外す

## 05. データモデル

設定ファイルは単一の JSON。Quick Launch の候補グループは入れ子の配列で表現し、参照や ID を持たせない。手で読み書きできることを優先する。

```json
{
  "version": 1,

  "variables": {
    "Proj": "D:\\work\\projects",
    "Share": "\\\\fileserver\\team\\dev"
  },

  "settings": {
    "quickLaunch": {
      "hotkey": "Alt+Space",
      "includeRecentFolders": true,
      "includeFrequentFolders": true,
      "includeOpenWindows": true,
      "includeBookmarks": true,
      "includeBrowserHistory": true,
      "includeApps": true,
      "azureDevOps": {
        "enabled": false,
        "projects": []
      },
      "includeEverything": false,
      "searchPaths": false,
      "visibleResults": 12
    },
    "startWithWindows": false
  },

  "items": [
    {
      "type": "folder",
      "name": "現在のプロジェクト",
      "path": "{Proj}\\waypoint",
      "open": "reuse",
      "showBranch": true
    },
    { "type": "separator", "name": "開発" },
    {
      "type": "submenu",
      "name": "ビルド出力",
      "items": [
        { "type": "folder", "name": "Debug",   "path": "{Proj}\\waypoint\\target\\debug" },
        { "type": "folder", "name": "Release", "path": "{Proj}\\waypoint\\target\\release" }
      ]
    },
    {
      "type": "specialFolder",
      "name": "ダウンロード",
      "knownFolder": "Downloads"
    }
  ]
}
```

上の JSON の登録項目は Quick Launch の候補として検索される。`submenu` は候補名にグループ名を付与し、`separator` は検索対象にしない。

```
現在のプロジェクト
ビルド出力 / Debug
ビルド出力 / Release
ダウンロード
```

### フィールド定義

| フィールド | 必須 | 内容 |
|---|---|---|
| `type` | 必須 | `folder` / `file` / `specialFolder` / `submenu` / `separator` |
| `name` | 必須 | Quick Launch に表示する文字列。`separator` では省略可 |
| `path` | `folder` / `file` | 絶対パス。変数を含んでよい |
| `knownFolder` | `specialFolder` のみ | 既知フォルダの識別名。`Downloads`、`Desktop` など |
| `items` | `submenu` のみ | 子項目の配列 |
| `open` | 任意 | `folder` / `specialFolder` のみ。`newWindow`（既定）または `reuse` |
| `icon` | 任意 | `folder` / `file`。アイコンファイルのパス。省略時はシステム既定 |
| `showBranch` | 任意 | `folder` / `submenu`。真のとき Git ブランチ名を候補名の後ろに表示する。`submenu` では配下の全 `folder` に継承される。既定は偽 |

## 06. 非機能要件

| 項目 | 目標値 | 備考 |
|---|---|---|
| Quick Launch 表示遅延 | 50ms 以内 | ホットキーまたはトレイ操作から描画完了まで。体感で最も重要な指標 |
| 常駐メモリ | 60MB 以下 | ワーキングセット。常時起動のため |
| 起動時間 | 1.5 秒以内 | Windows ログオンからトレイ常駐まで |
| DPI 対応 | Per-Monitor V2 | 複数モニタでスケーリングが異なる環境を想定する |
| ダークモード | 対応 | Quick Launch と管理画面はシステムテーマに従う |
| 長いパス | 260 文字超に対応 | ネットワークパスで到達しうる |
| ログ | ファイル出力 | `%APPDATA%\waypoint\log.txt`。起動・設定読込・エラーのみ記録 |

## 07. 技術構成

常駐部と Quick Launch は **Rust + `windows` crate**、管理画面は **.NET 8 + WPF** で実装する。管理画面は必要時のみ別プロセスで起動し、保存後は `PostMessage` で常駐部へ設定の再読み込みを通知する。

### Rust を選ぶ理由

仕様書のコア機能（Quick Launch・ホットキー・トレイ常駐）は**すべて生 Win32 API** を使う。Rust なら `windows` crate から直接叩けて中間層がない。

加えて:

- **常駐アプリとして軽い**: ランタイム非依存のネイティブバイナリ。release ビルドで 129KB（実測）。非機能要件の常駐メモリ 60MB 以下・起動 1.5 秒以内に対して余裕がある
- **手元に実例がある**: `E:\Windows-ComputerUse`（同じ作者の Rust プロジェクト）で `SHGetKnownFolderPath`・`GetForegroundWindow`・`SetForegroundWindow` が既に稼働している
- **必要な API は検証済み**: `RegisterHotKey` と Win32 ウィンドウ API が `windows` crate でコンパイルを通ることを確認済み

### 構成

| 層 | 実装 | 備考 |
|---|---|---|
| Quick Launch | 独自 Win32 ウィンドウ | 検索・選択・描画を一つのウィンドウで完結する |
| Win32 バインディング | `windows` crate 0.62 | 必要な feature のみ有効化 |
| ホットキー | `RegisterHotKey` + メッセージ専用ウィンドウ | `HWND_MESSAGE` の子で `WM_HOTKEY` を受ける |
| エクスプローラー操作 | `IShellWindows` (COM) | ウィンドウ列挙と `Navigate`。`COINIT_APARTMENTTHREADED` で初期化 |
| 既知フォルダ解決 | `SHGetKnownFolderPath` | GUID 表を持つ |
| アイコン取得 | `SHGetFileInfo` | 取得結果をパス単位でキャッシュする |
| トレイアイコン | `Shell_NotifyIcon` | 実装済み (`src/tray.rs`) |
| 管理画面 | .NET 8 / WPF | 別プロセスで必要時のみ起動。常駐部とは設定ファイルと `PostMessage` で連携 |
| 設定の入出力 | `serde` + `serde_json` | `preserve_order` で項目順を保つ |
| 二重起動抑止 | 名前付き Mutex | 既存プロセスへの通知は `PostMessage` |

## 08. リスクと制約

実装前に把握しておくべき既知の落とし穴。上ほど早期に踏む。**実装時は `AGENTS.md` の "Known pitfalls" を参照すること**（同じ内容を実装者向けに整理してある）。

### その他の制約

| ID | 制約 | 対応 |
|---|---|---|
| R-1 | 管理者権限で動作するアプリのウィンドウには、メッセージが届かない（UIPI） | 仕様として受け入れる。対応しない |
| R-2 | COM (`IShellWindows`) は STA を要求する | `CoInitializeEx(COINIT_APARTMENTTHREADED)` で初期化し、UI スレッドから呼ぶ |
| R-3 | ネットワークパスの存在確認がタイムアウトすると Quick Launch が固まる | 存在確認は非同期で行い、結果が返るまでは通常表示とする |
| R-4 | 常駐中の exe は上書きできない。インストーラが実行中プロセスを掴んだままだと更新に失敗する | MSI のアンインストール／アップグレード時に `waypoint.exe` を終了させる (`util:CloseApplication`) |

## 08-2. 配布形態

第三者向けの配布はしないが、自分の複数マシンへ同じ構成で入れ直すために MSI を作る。

| 項目 | 決定 | 理由 |
|---|---|---|
| 形式 | WiX 5 による MSI | `installer/waypoint.wxs`。アップグレード・アンインストールが標準で付く |
| アーキテクチャ | x64 のみ | ARM64 機でもエミュレーションで動作する。ビルドとリリースを 1 本に保つ |
| スコープ | ユーザー単位 (`perUser`) | 設定 (`%APPDATA%`) も自動起動 (`HKCU`) もユーザー単位なので整合する。UAC が出ない |
| インストール先 | `%LOCALAPPDATA%\Programs\waypoint` | `perUser` では `ProgramFiles` を使えない |
| 同梱物 | `waypoint.exe` / `waypoint-settings.exe` / `waypoint-tab-host.exe` / ブラウザ拡張 | タブ検索の Native Messaging host と Chrome / Edge 拡張を含む |
| ショートカット | スタートメニューに `waypoint` | インストール後すぐ起動できるように |
| 自動起動 | 初回インストール時のみ MSI が既定で有効にする | アプリ本体を `--enable-autostart-once` で一度だけ起動し、トレイの手動トグル (FR-8.4) と同じ関数でレジストリを書く。MSI がレジストリ値自体を Component として持たないため、ユーザーが後で OFF にしてもアップグレード時に勝手に ON へ戻らない (二重管理を避ける) |
| 拡張導入案内 | 初回の対話的インストール完了後にローカル HTML を開く | 開発者モード・「開梱された読み込み」・選択対象フォルダをその場で示す。サイレント導入・アップグレード時は開かない |
| 署名 | しない | R-7 のとおり |

## 10. 将来拡張
