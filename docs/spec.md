# waypoint 仕様書

| | |
|---|---|
| 版 | v0.2 (draft) |
| 状態 | 開発初期 / 土台のみ |
| 対象 | Windows 10 22H2 以降 |

Windows 向けの常駐型ランチャー。ホットキーまたは中マウスボタンで階層ポップアップメニューを開き、登録した場所やアプリへ一手で移動・起動する。Quick Access Popup の中核機能をベースに、フォルダ移動を主軸としつつアプリ起動・ブックマーク検索まで扱う汎用ランチャーとして再構成したもの。

> **v0.1 からの変更**: 実装言語を C#/WPF から **Rust + windows crate** に変更（07 章）。アプリ名を FolderPop から **waypoint** に変更。

---

## 01. 概要

### 目的

日常的に使う場所への移動コストをゼロに近づける。デスクトップのショートカット、エクスプローラーのクイックアクセス、タスクバーのピン留めに分散している導線を、ひとつのポップアップメニューに集約する。

### 想定ユーザー

作成者本人のみ。複数プロジェクトのソースツリー、ビルド出力、ログ、ドキュメントの各フォルダを一日に何十回も行き来する開発者。設定ファイルを直接編集することに抵抗がなく、GUI とテキストの両方から設定を触りたい。

### 成功の判定

本人が 2 週間連続で毎日使い、既存のショートカット群を消しても不便を感じないこと。それ以外の指標（ユーザー数、配布、ストア公開）は追わない。

### 非目標

- テキスト展開・ホットストリングは対象外。キーストローク送出のミニ言語は実装しない
- ファイル検索機能を持たない。インデックス作成は行わない（アプリ起動はスタートメニュー / インストール済みショートカットの列挙に限る。ファイルシステム全体の走査はしない）
- 第三者への配布を前提としない。自動更新、多言語化は作らない
- ただし**インストーラ (MSI) は作る**。自分の複数マシンへ同じ構成で入れ直すため（02 章参照）
- ファイラー固有の操作 API には対応しない。新規表示は Windows の既定フォルダーハンドラーに従う

## 02. スコープ

Quick Access Popup の全機能を分解し、本プロジェクトでの扱いを確定させる。**採用** は v1.0 に含む。**保留** は v1.0 の後に再検討する。**除外** は作らないと決めたもので、再検討もしない。

| 機能軸 | 判定 | 理由 |
|---|---|---|
| ポップアップメニュー表示 | **採用** | 本体。これが無ければ何も始まらない |
| フォルダ型お気に入り | **採用** | 本体 |
| 特殊フォルダ（既知フォルダ） | **採用** | KNOWNFOLDERID の対応表を持つだけで済む。費用対効果が高い |
| My Special Folders | **採用** | よく使う既知フォルダと Windows シェル名前空間への固定入口を QAP と同じ構成で提供する |
| サブメニュー・区切り・アイコン | **採用** | 登録数が 20 を超えた時点で階層化が必須になる |
| 変数展開（環境変数・ユーザー変数） | **採用** | ネットワークパスとユーザープロファイル配下のパスが長く、実質必須 |
| 管理 GUI | **採用** | 本人の希望により第 1 版から含める。工数の最大項目 |
| フォルダ構造の一括取り込み | **採用** | 起点フォルダと探索深度からメニュー階層を一度生成し、登録作業を短縮する |
| ライブフォルダ（動的展開） | 保留 | プロジェクトフォルダ配下の一覧に効くが、フィルタ仕様が膨らみやすい |
| ファイルダイアログ内のフォルダ切替 | 保留 | 価値は高いがダイアログ判定が泥臭い。エクスプローラー対応が安定してから |
| Quick Launch（クイック検索） | **採用** | 登録数が増えたため、名前を入力してキーボードだけで目的のフォルダを開けるようにする |
| In the Works（Recent / Frequent のフォルダ・ファイル） | **採用** | Windows の Recent Items をローカル集計し、作業中の項目へ素早く戻るために使う |
| Current Windows | **採用** | 現在開いている Explorer とアプリのウィンドウへ切り替える |
| ブラウザブックマーク検索 | **採用** | Quick Launch で `b ` に続けて入力すると Chrome / Edge のブックマークだけを検索し、選択すると既定ブラウザで開く。フォルダ移動ではないが Quick Launch の検索窓を流用でき、追加コストが小さい |
| アプリ起動（インストール済みアプリの検索・起動） | **採用** | スタートメニューのショートカット (`.lnk`) を列挙し、Quick Launch で `a ` に続けて入力すると検索できる。フォルダ・ブックマークと同じ「検索して一手で開く」体験に揃える。ファイルシステム全体のインデックス化はしない |
| Git ブランチ名の表示 | **採用** | 同一リポジトリの複数ワークツリーを使い分けるため、ジャンプ先の判断材料として必要。項目ごとのオプトインに限定し、表示経路では `.git/HEAD` のキャッシュのみ参照する |
| Reopen a Folder | 除外 | Current Windows と役割が重複し、ファイルダイアログ内のフォルダ切替も v1.0 の対象外 |
| スニペット / ホットストリング | 除外 | キーストローク送出のミニ言語を実装することになる。用途が無関係 |
| プレースホルダ（動的値挿入） | 除外 | 実質的に式評価エンジン。変数展開で代替する |
| グループ一括起動 | 除外 | 起動遅延やエラー時中断の制御が必要になり、単発起動を素早く行うという設計と衝突する。まとめて開きたい場合は個別に呼べば足りる |
| 共有メニュー / 設定同期 | 除外 | 単一ユーザーのため同期衝突の概念が存在しない |
| FTP サイト | 除外 | 用途なし |
| 電源操作・ウィンドウ管理 | 除外 | ランチャーの責務ではない |
| 他ファイラー固有連携（DOpus / TC） | 除外 | 各ファイラーの外部インターフェース仕様は扱わない。OS の既定フォルダーハンドラーは使用する |
| インストーラ (MSI) | **採用** | 常駐アプリなので置き場所とスタートメニュー登録を毎回手作業したくない。自分の複数マシンへ同じ構成で入れ直すために使う |
| 自動更新・多言語 | 除外 | 配布しないため不要。更新は MSI の再インストールで足りる |

> **スコープを守るための約束**
>
> 「除外」に入れた項目は、実装中に思いついても v1.0 では着手しない。追加したくなった場合は本表を書き換えてから着手する。**仕様書を更新せずに機能を足すことを禁止する。** この一文が本仕様書の存在意義である。

## 03. 用語

| 用語 | 定義 |
|---|---|
| 項目 | メニューに現れる 1 行。フォルダ・特殊フォルダ・サブメニュー・区切りのいずれかの型を持つ |
| メニュー | 項目の順序付きリスト。ルートメニューとサブメニューを区別しない |
| トリガー | メニューを表示させる入力操作。中クリックまたはホットキー |
| 元ウィンドウ | トリガーが押された時点で最前面だったウィンドウ。フォルダ変更の対象を決めるために保持する |
| 設定ファイル | 項目定義とアプリ設定を保持する JSON ファイル。単一ファイルとする |
| 常駐部 | トレイに常駐しトリガーを待ち受けるプロセス |
| 管理画面 | 項目を編集するウィンドウ。必要時のみ生成する |

## 04. 機能要件

### FR-1 トリガー

- **FR-1.1** マウス中ボタンの押下でメニューを表示する。既定で有効
- **FR-1.2** グローバルホットキーでメニューを表示する。既定は `Win+W`。設定で変更可能
- **FR-1.2.1** `RegisterHotKey` が失敗した場合（Windows 11 の Widgets が `Win+W` を予約済みなど）、低レベルキーボードフックで同じキーを横取りする。フックは OS のホットキー処理より手前で打鍵を受け取るため、既に他が握っているキーでも上書きできる。この場合、元の割り当て（Widgets など）はキーボードからは起動しなくなる
- **FR-1.3** トレイアイコンの左クリックでメニューを表示する
- **FR-1.4** 中ボタンの除外プロセス一覧を設定に持つ。一覧に含まれる実行ファイルが最前面のとき、中ボタンはアプリ側へそのまま通す。既定値に `chrome.exe`、`msedge.exe`、`firefox.exe` を含める
- **FR-1.5** 中ボタンの押下から解放までにカーソルが移動した場合、ドラッグ操作とみなしメニューを表示せずアプリ側へ通す
- **FR-1.6** トリガー検出時、元ウィンドウのハンドルを保持する

### FR-2 メニュー表示

- **FR-2.1** メニューはカーソル位置に表示する。画面端では自動的に反転させ、画面外にはみ出さない
- **FR-2.2** 設定ファイルの階層をそのままサブメニューとして展開する。ネストの深さに制限を設けない
- **FR-2.3** 各項目にアイコンを表示する。フォルダは既定のフォルダアイコン、特殊フォルダはシステムが返すアイコンを使う。寸法は `settings.menu.iconSize`（論理ピクセル、既定 32、範囲 16〜64）に従い、DPI に応じて拡大する
- **FR-2.3.1** アイコンは要求寸法以上のシステムイメージリスト（`SHIL_SMALL` / `SHIL_LARGE` / `SHIL_EXTRALARGE` / `SHIL_JUMBO`）から取得する。小さい素材を引き伸ばすと輪郭がにじむため、拡大ではなく縮小になるものを選ぶ
- **FR-2.3.2** メニュー項目はオーナードロー（`MFT_OWNERDRAW`）で描画し、行の高さをアイコンと文字の高いほうに余白を加えた値とする。`TrackPopupMenuEx` は `MIIM_BITMAP` のアイコン寸法を行高へ反映しないため、行高を制御する手段がこれしかない（実測で確認）。フォントはシステムのメニューフォント（`lfMenuFont`）をそのまま使い、文字の大きさは変更しない
- **FR-2.4** 項目名の先頭から数えて上位 9 件に `1`〜`9` の数字キーを自動割当し、キー入力で選択できるようにする
- **FR-2.5** `Esc` またはメニュー外クリックで表示を取り消す
- **FR-2.6** 存在しないパスを指す項目はグレー表示にする。選択しても何も起きない
- **FR-2.7** ランチャーメニューは Windows のダークメニューテーマで描画する。項目と区切り線はオーナードローで描き、色は uxtheme のメニューテーマから取る。**ポップアップを囲む外枠だけは対象外**とする（非クライアント領域のため制御手段がなく、v1.0 では明るいまま受け入れる。試した手法と結果は `AGENTS.md` に記録）
- **FR-2.8** ルートメニューの末尾に `Settings...`、`Reload config`、`Close this menu` を区切って表示する
- **FR-2.9** ルートに `In the Works` サブメニューを表示し、その中に `Recent Folders`、`Recent Files`、`Frequent Folders`、`Frequent Files`、`Current Windows` を表示する
- **FR-2.10** Recent は Windows の Recent Items に記録された更新日時順、Frequent は同じ記録をローカル集計した利用回数順とし、それぞれ最大 10 件を表示する
- **FR-2.11** Current Windows は表示中の Explorer とアプリのトップレベルウィンドウを列挙し、選択時に対象ウィンドウを前面へ移す
- **FR-2.12** 動的メニューの列挙と集計はメニュー表示経路では行わない。起動時とメニューを閉じた後にキャッシュを更新し、次回表示ではキャッシュのみ参照する
- **FR-2.13** ルートに `My Special Folders` サブメニューを表示する。`Desktop`、`Documents`、`Pictures`、`Downloads`、`This PC`、`Network`、`All Control Panel Items`、`Recycle Bin` と、特殊フォルダ追加・設定画面への入口を持つ
- **FR-2.14** `folder` 項目で `showBranch` が真のとき、パスが Git 作業ツリー内にあれば項目名の後ろに `[ブランチ名]` を付す。リポジトリでない場合、または解決できない場合は何も付さない。detached HEAD では短縮 SHA を表示する
- **FR-2.15** ブランチ名の取得は `git` コマンドを起動せず `.git/HEAD` の直読みで行う。FR-2.12 と同じくメニュー表示経路では行わず、メニュー構築時に読んだ値をそのまま使う。対象は `showBranch` が真の項目のみとし、全項目を走査しない

### FR-3 項目の型

| 型 | 保持する情報 | 選択時の動作 |
|---|---|---|
| `folder` | 表示名、パス、開き方、ブランチ表示の可否 | 指定パスを既定のフォルダーハンドラーで開く |
| `specialFolder` | 表示名、既知フォルダ ID | 解決したパスを既定のフォルダーハンドラーで開く |
| `submenu` | 表示名、子項目の配列 | サブメニューを展開する |
| `separator` | 表示名（省略可） | 選択不可。区切り線または見出しとして描画する |

### FR-4 フォルダを開く動作

- **FR-4.1** 開き方は `newWindow`（既定のフォルダーハンドラーで開く）と `reuse`（元ウィンドウのフォルダを変更）の 2 種。既定は `newWindow`
- **FR-4.2** `reuse` は元ウィンドウがエクスプローラーである場合のみ有効。それ以外は `newWindow` にフォールバックする
- **FR-4.3** `Shift` を押しながら選択した場合、項目の設定に関わらず `newWindow` で開く
- **FR-4.4** 開いたウィンドウは、トリガーが発生したモニタ上に配置する

### FR-5 変数展開

- **FR-5.1** パス中の `%NAME%` を Windows 環境変数として展開する
- **FR-5.2** パス中の `{NAME}` を設定ファイル内のユーザー変数として展開する
- **FR-5.3** 展開は項目の選択時ではなく設定の読み込み時に一度だけ行い、結果をメモリに保持する
- **FR-5.4** 解決できない変数を含む項目は起動時のログに記録し、メニューではグレー表示にする。アプリは停止しない

### FR-6 管理画面

- **FR-6.1** QAP の Customize 画面に合わせ、上部で編集対象のメニューを選び、中央に選択中メニューの項目一覧を表示する
- **FR-6.2** 項目の追加・編集・削除・複製ができる
- **FR-6.3** 一覧内で項目の順序を上下ボタンで変更できる。加えて、行をドラッグして任意の位置へ落とすことでも並べ替えられる。ドラッグ中は挿入位置を線で示す
- **FR-6.4** フォルダ選択ダイアログからパスを指定できる
- **FR-6.5** エクスプローラーからのドラッグ＆ドロップで項目を追加できる
- **FR-6.6** 保存ボタンで設定ファイルへ書き出し、常駐部へ再読み込みを通知してメニューを再構築する。保存前に閉じようとした場合は確認する
- **FR-6.7** ユーザー変数を編集する画面を持つ
- **FR-6.8** 除外プロセス一覧とホットキーを編集する設定画面を持つ
- **FR-6.8.1** ホットキーは文字列の直接入力に加え、実際のキー入力から設定できる。記録中は打鍵を OS へ渡さず、`Win+W` のようにシステムが予約している組み合わせもそのまま記録できる。`Esc` で取り消す
- **FR-6.9** 起点フォルダと探索深度（0〜10）を指定し、サブフォルダ構造をメニュー階層として一括取り込みできる。取り込み前に名称変更と除外ができ、確定後は通常の項目編集・並べ替えを利用できる
- **FR-6.10** 取り込みは確定時の一度だけ行い、元フォルダとの自動同期は行わない

> 管理画面は Rust + `egui/eframe` の別プロセスとして実装する。必要時だけ起動し、常駐部の起動時間・メモリ・メッセージループへ影響させない。

### FR-7 設定の永続化

- **FR-7.1** 設定は `%APPDATA%\waypoint\config.json` に保存する
- **FR-7.2** 起動時に設定ファイルが無い場合、既定の設定を生成する
- **FR-7.3** 保存時、既存ファイルを退避してから書き込む（temp に書いて置換する原子的更新）
- **FR-7.4** JSON の解析に失敗した場合、空メニューで起動し、トレイ通知でエラーを知らせる。設定ファイルは上書きしない
- **FR-7.5** 手編集を想定し、インデント 2 桁・日本語は非エスケープ・**項目順を保存で入れ替えない**（`serde_json` の `preserve_order`）
- **FR-7.6** Recent Items の利用回数は `%APPDATA%\waypoint\history.json` にローカル保存する。外部へ送信しない

### FR-8 常駐とライフサイクル

- **FR-8.1** 起動時にタスクトレイへ常駐する。ウィンドウは表示しない
- **FR-8.2** トレイアイコンの右クリックメニューに「設定を開く」「設定を再読み込み」「終了」を持つ
- **FR-8.3** 二重起動を抑止する。二つ目のプロセスは既存プロセスにメニュー表示を要求して終了する
- **FR-8.4** Windows 起動時の自動実行を設定で切り替えられる

### FR-9 Quick Launch

- **FR-9.1** 設定可能なグローバルホットキー（既定 `Ctrl+Shift+Q`）で検索画面を開く
- **FR-9.2** 登録済みの `folder` / `specialFolder` と、設定で有効にした Recent / Frequent Folders を検索対象にする。Current Windows / ブックマーク / アプリはプレフィックスモード限定（FR-9.13〜9.15）
- **FR-9.3** 項目名と所属サブメニューのパンくずを、大文字小文字を区別しない部分一致で検索する。空白区切りの語は AND 条件とする
- **FR-9.4** パス検索は設定で有効化できる。検索中にパスの存在確認やネットワークアクセスを行わない
- **FR-9.5** 名前の完全一致、先頭一致、単語境界一致、部分一致、パンくず一致、パス一致の順に候補を並べ、同点ではメニュー順を保つ
- **FR-9.6** 候補には名前、パンくず、解決済みパスを表示し、同名項目を判別できるようにする
- **FR-9.7** `Up` / `Down` / `Home` / `End` / `PageUp` / `PageDown` で候補を移動し、`Enter` で実行、`Esc` またはフォーカス喪失で閉じる
- **FR-9.8** `Shift+Enter` は常に `newWindow`、`Ctrl+Enter` は常に `reuse` として開く。開き方を持たない候補（Current Windows・ブックマーク・アプリ）はこの修飾を無視する
- **FR-9.9** 検索インデックスは起動時、設定再読み込み時、動的メニュー更新後に構築する。キー入力時はメモリ上の検索だけを行う
- **FR-9.10** 検索画面は常駐プロセス内の標準 Win32 コントロールで実装し、管理画面プロセスを起動しない
- **FR-9.11** 検索画面は黒を基調とし、`Segoe UI Variable Text`、Windows 11 の角丸・ダークタイトルバー、青系の選択色を使う。未対応環境では通常の Win32 表示へフォールバックする
- **FR-9.12** 候補はフォルダーアイコン、名前、パンくずとパスの 2 段を高密度に描画し、DPI に応じてフォント・余白・行高を拡縮する。表示件数は 12〜24 件、既定は 12 件とする
- **FR-9.13** 入力が `b ` (半角スペース込み) で始まる間は通常の検索対象を隠し、Chrome / Edge のブックマークだけを残りの文字列で検索する。選択すると既定ブラウザで URL を開く。ブックマーク取り込みは設定で無効化できる
- **FR-9.14** 入力が `a ` (半角スペース込み) で始まる間は通常の検索対象を隠し、スタートメニューのショートカット (`.lnk`) だけを残りの文字列で検索する。選択すると対象アプリを起動する。アプリ検索は設定で無効化できる
- **FR-9.15** 入力が `w ` (半角スペース込み) で始まる間は通常の検索対象を隠し、Current Windows だけを残りの文字列で検索する。選択すると対象ウィンドウへ切り替える。Current Windows の取り込みは設定で無効化できる

## 05. データモデル

設定ファイルは単一の JSON。メニュー階層はそのまま入れ子の配列で表現し、参照や ID を持たせない。手で読み書きできることを優先する。

```json
{
  "version": 1,

  "variables": {
    "Proj": "D:\\work\\projects",
    "Share": "\\\\fileserver\\team\\dev"
  },

  "settings": {
    "trigger": {
      "middleClick": true,
      "hotkey": "Win+W",
      "excludedProcesses": ["chrome.exe", "msedge.exe", "firefox.exe"]
    },
    "menu": {
      "iconSize": 32,
      "numericAccelerators": true
    },
    "quickLaunch": {
      "hotkey": "Ctrl+Shift+Q",
      "includeRecentFolders": true,
      "includeFrequentFolders": true,
      "includeOpenWindows": true,
      "includeBookmarks": true,
      "includeApps": true,
      "searchPaths": false,
      "visibleResults": 12
    },
    "startWithWindows": false
  },

  "items": [
    {
      "type": "folder",
      "name": "現在のプロジェクト",
      "path": "{Proj}\\waypoint",
      "open": "reuse",
      "showBranch": true
    },
    { "type": "separator", "name": "開発" },
    {
      "type": "submenu",
      "name": "ビルド出力",
      "items": [
        { "type": "folder", "name": "Debug",   "path": "{Proj}\\waypoint\\target\\debug" },
        { "type": "folder", "name": "Release", "path": "{Proj}\\waypoint\\target\\release" }
      ]
    },
    {
      "type": "specialFolder",
      "name": "ダウンロード",
      "knownFolder": "Downloads"
    }
  ]
}
```

上の JSON は次のメニューとして描画される。

```
┌─────────────────────────────┐
│  現在のプロジェクト              1 │
│  ─────── 開発 ───────         │
│  ビルド出力                  2 ▸ │──┬─ Debug
│  ダウンロード                  3 │  └─ Release
└─────────────────────────────┘
```

### フィールド定義

| フィールド | 必須 | 内容 |
|---|---|---|
| `type` | 必須 | `folder` / `specialFolder` / `submenu` / `separator` |
| `name` | 必須 | メニューに表示する文字列。`separator` では省略時に単純な区切り線 |
| `path` | `folder` のみ | 絶対パス。変数を含んでよい |
| `knownFolder` | `specialFolder` のみ | 既知フォルダの識別名。`Downloads`、`Desktop` など |
| `items` | `submenu` のみ | 子項目の配列 |
| `open` | 任意 | `newWindow`（既定）または `reuse` |
| `icon` | 任意 | アイコンファイルのパス。省略時はシステム既定 |
| `showBranch` | 任意 | `folder` のみ。真のとき Git ブランチ名を項目名の後ろに表示する。既定は偽 |

## 06. 非機能要件

| 項目 | 目標値 | 備考 |
|---|---|---|
| メニュー表示遅延 | 50ms 以内 | トリガー検出から描画完了まで。体感で最も重要な指標 |
| 常駐メモリ | 60MB 以下 | ワーキングセット。常時起動のため |
| 起動時間 | 1.5 秒以内 | Windows ログオンからトレイ常駐まで |
| フック応答時間 | 10ms 以内 | 低レベルフックのコールバック内。超過するとフックが外される |
| DPI 対応 | Per-Monitor V2 | 複数モニタでスケーリングが異なる環境を想定する |
| ダークモード | 対応 | ランチャーメニューはダーク表示、管理画面はシステムテーマに従う |
| 長いパス | 260 文字超に対応 | ネットワークパスで到達しうる |
| ログ | ファイル出力 | `%APPDATA%\waypoint\log.txt`。起動・設定読込・エラーのみ記録 |

## 07. 技術構成

常駐部は **Rust + `windows` crate**、管理画面は **Rust + `egui/eframe`** で実装する。管理画面は必要時のみ別プロセスで起動し、保存後は `PostMessage` で常駐部へ設定の再読み込みを通知する。

### Rust を選ぶ理由

仕様書のコア機能（ポップアップ・低レベルフック・ホットキー）は**すべて生 Win32 API** であり、どの言語を選んでもバインディング越しの呼び出しになる。Rust なら `windows` crate から直接叩けて中間層がない。

加えて:

- **常駐アプリとして軽い**: ランタイム非依存のネイティブバイナリ。release ビルドで 129KB（実測）。非機能要件の常駐メモリ 60MB 以下・起動 1.5 秒以内に対して余裕がある
- **手元に実例がある**: `E:\Windows-ComputerUse`（同じ作者の Rust プロジェクト）で `SHGetKnownFolderPath`・`GetForegroundWindow`・`SetForegroundWindow` が既に稼働している
- **P0 の API は検証済み**: `CreatePopupMenu` / `TrackPopupMenuEx` / `SetWindowsHookExW(WH_MOUSE_LL)` / `RegisterHotKey` が `windows` 0.62.2 でコンパイルを通ることを確認済み

### 構成

| 層 | 実装 | 備考 |
|---|---|---|
| ポップアップメニュー | `CreatePopupMenu` / `TrackPopupMenuEx` | ネイティブの描画と挙動をそのまま使う。ウィンドウ不要 |
| Win32 バインディング | `windows` crate 0.62 | 必要な feature のみ有効化 |
| 中ボタン検出 | `SetWindowsHookExW(WH_MOUSE_LL)` | マウスは `RegisterHotKey` の対象外のため低レベルフックが必須 |
| ホットキー | `RegisterHotKey` + メッセージ専用ウィンドウ | `HWND_MESSAGE` の子で `WM_HOTKEY` を受ける |
| エクスプローラー操作 | `IShellWindows` (COM) | ウィンドウ列挙と `Navigate`。`COINIT_APARTMENTTHREADED` で初期化 |
| 既知フォルダ解決 | `SHGetKnownFolderPath` | GUID 表を持つ |
| アイコン取得 | `SHGetFileInfo` | 取得結果をパス単位でキャッシュする |
| トレイアイコン | `Shell_NotifyIcon` | 実装済み (`src/tray.rs`) |
| 管理画面 | `egui/eframe` | 別プロセスで必要時のみ起動。常駐部とは設定ファイルと `PostMessage` で連携 |
| 設定の入出力 | `serde` + `serde_json` | `preserve_order` で項目順を保つ |
| 二重起動抑止 | 名前付き Mutex | 既存プロセスへの通知は `PostMessage` |

## 08. リスクと制約

実装前に把握しておくべき既知の落とし穴。上ほど早期に踏む。**実装時は `AGENTS.md` の "Known pitfalls" を参照すること**（同じ内容を実装者向けに整理してある）。

### R-1 中ボタンフックが他アプリの操作を壊す

低レベルフックで中ボタンを無条件に横取りすると、ブラウザのオートスクロールとリンクの新規タブオープンが機能しなくなる。QAP が除外アプリのリスト機能を持つのはこのため。**FR-1.4 の除外リストと FR-1.5 のドラッグ判定を最初の実装に含めること。** 後付けにすると設計の作り直しになる。

### R-2 TrackPopupMenuEx はフォアグラウンドを要求する

呼び出し元ウィンドウが最前面でないと、メニュー外をクリックしてもメニューが閉じない。直前に `SetForegroundWindow` を呼ぶ必要がある。Win32 の古典的なハマりどころ。

### R-3 元ウィンドウのハンドルを失う

メニューを表示した瞬間に自分自身が最前面になるため、「元のエクスプローラーウィンドウのフォルダを変更する」の対象が分からなくなる。トリガー検出の時点で `GetForegroundWindow` の結果を保持しておくこと（FR-1.6）。

### R-4 フックのコールバックがタイムアウトすると黙って外される

低レベルフックの応答がレジストリの `LowLevelHooksTimeout`（既定 300ms）を超えると、Windows はフックを通知なく解除する。以後トリガーが効かなくなり、再現しづらい不具合になる。**フック内では判定のみ行い、メニュー構築と表示は `PostMessage` した先で実行すること。**

### その他の制約

| ID | 制約 | 対応 |
|---|---|---|
| R-5 | 管理者権限で動作するアプリのウィンドウには、フックもメッセージも届かない（UIPI） | 仕様として受け入れる。対応しない |
| R-6 | `TrackPopupMenuEx` の座標は物理ピクセル | Per-Monitor V2 を宣言し、変換を 1 箇所に閉じ込める |
| R-7 | 署名のない実行ファイルが低レベルフックを張ると Defender に検知される可能性がある | 自分の環境で除外設定を行う。第三者へ配布しないため証明書は取得しない。MSI も未署名 |
| R-8 | COM (`IShellWindows`) は STA を要求する | `CoInitializeEx(COINIT_APARTMENTTHREADED)` で初期化し、UI スレッドから呼ぶ |
| R-9 | ネットワークパスの存在確認がタイムアウトするとメニュー表示が固まる | 存在確認は非同期で行い、結果が返るまでは通常表示とする |
| R-10 | 常駐中の exe は上書きできない。インストーラが実行中プロセスを掴んだままだと更新に失敗する | MSI のアンインストール／アップグレード時に `waypoint.exe` を終了させる (`util:CloseApplication`) |

## 08-2. 配布形態

第三者向けの配布はしないが、自分の複数マシンへ同じ構成で入れ直すために MSI を作る。

| 項目 | 決定 | 理由 |
|---|---|---|
| 形式 | WiX 5 による MSI | `installer/waypoint.wxs`。アップグレード・アンインストールが標準で付く |
| アーキテクチャ | x64 のみ | ARM64 機でもエミュレーションで動作する。ビルドとリリースを 1 本に保つ |
| スコープ | ユーザー単位 (`perUser`) | 設定 (`%APPDATA%`) も自動起動 (`HKCU`) もユーザー単位なので整合する。UAC が出ない |
| インストール先 | `%LOCALAPPDATA%\Programs\waypoint` | `perUser` では `ProgramFiles` を使えない |
| 同梱物 | `waypoint.exe` / `waypoint-settings.exe` | 常駐部と管理画面 |
| ショートカット | スタートメニューに `waypoint` | インストール後すぐ起動できるように |
| 自動起動 | 初回インストール時のみ MSI が既定で有効にする | アプリ本体を `--enable-autostart-once` で一度だけ起動し、トレイの手動トグル (FR-8.4) と同じ関数でレジストリを書く。MSI がレジストリ値自体を Component として持たないため、ユーザーが後で OFF にしてもアップグレード時に勝手に ON へ戻らない (二重管理を避ける) |
| 署名 | しない | R-7 のとおり |

## 09. フェーズ計画

各フェーズは受入条件を満たした時点で完了とし、次に進む。工数の目安は週末の作業回数。

### P0 技術検証 — 1〜2 日

製品コードを書かず、使い捨てで 4 点だけ確認する。ここで詰まる場合は技術構成そのものを見直す。

- `TrackPopupMenuEx` でカーソル位置に 2 階層のメニューを表示する
- `WH_MOUSE_LL` で中ボタンを検出し、ブラウザのオートスクロールを壊さないことを確認する
- `RegisterHotKey` で `Win+W` を受け取る
- `IShellWindows` でエクスプローラーのウィンドウを列挙し、フォルダを変更する

**受入条件**: 4 項目すべてが動作し、R-1 と R-2 の挙動を実機で確認できている。

> 4 項目とも `windows` crate で**コンパイルが通ることは確認済み**。残るは実挙動の確認。

### P1 動く最小版 — 週末 2 回

- FR-7 設定ファイルの読み込み（書き込みは手編集のみ）
- FR-2 メニュー構築、FR-3 の `folder` / `submenu` / `separator`
- FR-4.1 の `newWindow` のみ
- FR-1.1 / FR-1.2 / FR-1.4 / FR-1.5、FR-8.1 / FR-8.2 / FR-8.3

**受入条件**: 自分の実フォルダを 10 件以上登録し、1 日通して使えている。既存のショートカットを 1 つ消せる。

### P2 管理画面 — 週末 3〜4 回

全工程で最も重い。意識的に機能を絞ること。**着手前に GUI 方式を決める。**

- FR-6.1〜FR-6.6
- FR-7.3 バックアップ付き保存、保存後のメニュー再構築

**受入条件**: JSON を直接開かずに、項目の追加から保存・反映まで完結する。

### P3 エクスプローラー連携 — 週末 2 回

- FR-4.2 `reuse` による元ウィンドウのフォルダ変更、FR-4.3 `Shift` による上書き
- FR-3 の `specialFolder`、FR-5 変数展開
- FR-2.6 存在しないパスのグレー表示

**受入条件**: エクスプローラーを開いた状態から、新しいウィンドウを増やさずにフォルダを移動できる。

### P4 仕上げ — 週末 1〜2 回

- FR-2.3 アイコン表示とキャッシュ、FR-2.4 数字アクセラレータ
- FR-6.5 ドラッグ＆ドロップによる項目追加、FR-6.7 / FR-6.8 設定画面
- FR-8.4 自動起動、非機能要件の実測

**受入条件**: 非機能要件の目標値をすべて満たす。2 週間連続で使用し、不足を感じた点を記録する。
